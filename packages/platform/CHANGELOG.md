# Changelog

All notable changes to `@agentic/platform` (Keep a Changelog, semver).

## [Unreleased]

- Notification channels are plugins (#244, part of #224; AST-06, AST-07, PLG-01): `defineInbox({ channelPlugins, registry })` asks `Registry.gate()` ONCE per notification which `notification` plugins are on and opens each one it has a `ChannelPlugin` for, `open({ config, secret(name) })` — config merged over the defaults, secrets through `openSecret` as the workspace owner (enabled + granted, audited), a missing one `undefined`. A plugin that is off is never opened. A Registry that cannot be asked is a failed `DeliveryAttempt` on channel `PLUGIN_CHANNELS` (`plugins`); the static `channels` still deliver. New `webPushPlugin` (`agentic.notify.web-push`, kind `notification`, config `{ subject (required, uri), publicKey }`, secret `vapid-private-key` with its `secret:` scope) and `webPushChannelPlugin(options)`: with no subscription it opens no secret and sends nothing; without a contact, a public key or the private key it records a failed attempt naming what is missing, never an unsigned push. `Inbox.subscriptions` is now a declared live read. New exports: `webPushPlugin`, `webPushChannelPlugin`, `WEB_PUSH_PLUGIN_ID`, `VAPID_PRIVATE_KEY_SECRET`, `PLUGIN_CHANNELS`, `ChannelPlugin`, `ChannelPluginContext`, `ChannelCatalogue`.

- Scope `usage` (#267, part of #261): in `ALL_SCOPES`, accepted on external principals, and on the consent screen as "See how close each account is to its provider's usage limits". Plugin kind `quota` is in `PLUGIN_KINDS`.
- Memory and learning through the active plugin (#242, part of #224; MEM-02, LRN-01, AC-13): a session uses the workspace's ACTIVE memory and learning plugin, over its config, from the gate `Routing.run` recorded on the spec (`spec.plugins`) — no second hop. `platformLearningPorts({ memoryPlugins, learningPlugins })` take the build's implementations by plugin id (`MemoryPluginImpl = (config) => PlatformMemory { open, retrieval? }`, `LearningPluginImpl = (config) => LearningPlugin | LearningPluginFactory`); `memoryAccess(ports, gate)` / `learningAccess(ports, gate)` resolve them to `SessionMemory` / `SessionLearning`. `memoryActorImpl()` (the default: `memoryActorPlugin` over the Memory actor as the calling principal — its first production caller) and `isolateMemoryImpl(make)` (a plugin with no ACL or durable backend, e.g. the flat one: one instance per workspace in the isolate, an agent's own scope only). A memory config's `retrievalLimit` is the session-start budget (`retrievalFromConfig`, `RETRIEVAL_LIMIT_KEY`; `0` asks no scope). Memory turned off (or an active id the build does not implement): nothing retrieved (the reason in `spec.retrieval.skipped`), written or learned, `correct` refuses, stored memories untouched; learning turned off: no `onTaskEnd`, `correct` refuses. `memory_search` / `memory_remember` reach the same store — `createActorToolPorts({ memory })`, `AnthropicApiRuntimeOptions.memory` and `createToolCallPort({ memory })` (which reads the calling session's gate only for a memory tool) — and, memory off, answer why (`ToolCallError('unsupported')`); both port methods now reject instead of throwing. No gate on the spec: the static ports, as before. New exports: `memoryAccess`, `learningAccess`, `MEMORY_OFF`, `LEARNING_OFF`, `memoryActorImpl`, `isolateMemoryImpl`, `retrievalFromConfig`, `RETRIEVAL_LIMIT_KEY`, `PlatformMemory`, `MemoryPluginImpl`, `LearningPluginImpl`, `SessionMemory`, `SessionLearning`.
- **Removed** `SessionFactoryOptions.anthropic` / `AnthropicApiRuntimeOptions.anthropic` (#231, deprecated in #230): the Anthropic key is only ever the workspace's `anthropic-api-key` Registry secret. Without a `registry`, `anthropicApiRuntime` opens only under the `model` seam and otherwise fails `no-api-key` naming `/plugins/anthropic-api`.
- Environments managed from the web (#237, part of #224; EXE-03/04, OPS-01/03; decisions 2026-09-19 (c)): `Machine.putEnvironment(input: EnvironmentInput)` / `removeEnvironment(environmentId)` → `{ requestId }` send `env.request`, and `Machine.envResult(requestId)` → `EnvResultView` reads the daemon's `env.response` (live-keyable, like `fsRequest` / `fsResult`). Owner only, and on no tool surface. The input is validated by the strict protocol schema (400 — a `profileDir` is refused); 403 revoked, 503 `machine-offline`; `removeEnvironment` 404 for an environment the machine does not report and 409 `in-use` while it hosts or queues a session there. The daemon's error code is stored unchanged. Pending requests fail `timeout` at `MachinePorts.envTimeoutMs` (default 30 s) through the `liveness` reminder and on disconnect or revoke; a late answer still lands. At most `MAX_ENV_REQUESTS` = 16, finished ones pruned after `ENV_RESULT_TTL_MS` = 2 min. `MachineView.policy` / `MachineState.policy` hold the `MachinePolicy` from `hello` (replaced, or dropped when a daemon reports none) and `env` (updated when present). New audit kinds `environment.put { machineId, environmentId?, name, runtime, cwdRoots, outcome }` and `environment.removed { machineId, environmentId, outcome }`, recorded once per answered request under the owner who asked. New exports: `EnvRequestRecord`, `EnvRequested`, `EnvResultView`, `MAX_ENV_REQUESTS`, `ENV_RESULT_TTL_MS`, `DEFAULT_ENV_TIMEOUT_MS`, `MACHINE_OFFLINE_CODE`, `EnvironmentPutData`, `EnvironmentRemovedData`.
- Routing and the session factory over the Registry (#230, part of #224; AC-13, EXE-10, EXE-12, AGT-05): `defineRoutingActor({ registry?, runtimes? })` asks `Registry.gate({ runtime })` ONCE in `run`, before a route is written — a runtime plugin that is missing or turned off fails the task `plugin-disabled` (recoverable; its chat is told), a Registry that cannot be asked `registry-unavailable`, and a `fallback-api` asks again for `anthropic-api` before the task leaves its environment. The answer is kept on the route (`Route.plugins`) and recorded on the session spec (`SessionOpenSpec.plugins: RegistryGate`), so memory / learning / connectors need no second hop; the runtime plugin's `config.defaultModel` fills in where the agent names no model (both paths). New `RuntimeCatalogue` (`Record<string, RuntimeImpl>` or a function) with `RuntimeImpl = { host: 'local'; open(context, plugin: RuntimePluginAccess) } | { host: 'daemon' }`: the router places a `local` runtime in-process and a `daemon` one on a machine, and an id the catalogue lacks fails `unknown-runtime` (router and factory alike); without a catalogue `anthropic-api` is local and every other id a daemon's, as before. `createSessionFactory({ runtimes?, registry? })` looks the runtime up; the built-in body is now the exported `anthropicApiRuntime(options)`. With a `registry` the Anthropic key is the workspace's `anthropic-api-key` secret — `Registry.openSecret` as the workspace owner, once per session open (audited `secret.opened`), never kept in the isolate, asked for even under the `model` seam; a missing key fails the open `no-api-key` naming `/plugins/anthropic-api`, and a plugin turned off between the gate and the open fails the task `plugin-disabled`, not `session-open`. `SessionFactoryOptions.anthropic` is **deprecated** (only read when there is no `registry`; #231 removes it). New exports: `anthropicApiRuntime`, `resolveRuntime`, `PLUGIN_DISABLED_CODE`, `UNKNOWN_RUNTIME_CODE`, `AnthropicApiRuntimeOptions`, `RuntimeCatalogue`, `RuntimeImpl`, `RuntimePluginAccess`. A daemon-runtime task with no environment of its own, its agent's or a delegating task's now runs in the workspace's `defaults.environmentId` (`environment.chosen` says `the workspace's default`) before failing `no-environment`.
- Workspace settings are core's (#230 after #227): `WorkspaceSettings`, `WorkspaceDefaults`, `NotificationPrefs` and `RetentionSettings` are re-exported from `@agentic/core` and `DEFAULT_SETTINGS` is `DEFAULT_WORKSPACE_SETTINGS`. **Removed:** `defaults.model` — a model is the runtime plugin's to default (`anthropic-api` `config.defaultModel`); `updateSettings` rebuilds `defaults` from `runtime` and `environmentId`, so a stored or patched `model` is dropped on the next write.
- Registry catalogue (#229, part of #224; PLG-01..05, AC-13): `defineRegistry({ kek, catalogue })` takes the plugins the build ships (`CatalogueEntry` = a manifest, or `{ manifest, enabledByDefault? }`). Built-ins are virtual until touched — no record, read as enabled with every declared scope granted and the schema's defaults; no read saves, the first mutation materialises and saves in the turn; the build's manifest is always overlaid (undeclared grants lapse, a never-seen scope is granted once through `seenScopes`, a revoked one stays revoked); `register` over and `remove` of a built-in refuse `builtin`; `exportRows` emits effective rows. **Fix:** `configure` accepted any object — it (and `register`'s `config`) now validates against the manifest's `ConfigSchema` with defaults filled in and throws `BadConfigError` (`bad-config`, `errors[]` by path). `assertPluginManifest` checks `manifest.secrets` and requires the matching `secret:` permission. Single-slot kinds: `state.active`, owner-only `activate(kind, id)` (`wrong-kind`; new audit kind `plugin.activated { pluginId, kind, previous? }`). New reads: `gate({ runtime? })` → `RegistryGate` (one hop for `Routing.run`), `overview()` → `RegistryOverview` (live), `dependentsAll()` → `Dependents[]` over one workspace walk; `collectRefs` now reads agents and schedules side by side. `PluginView` gains `builtin` and `active?` and its `config` is merged over the defaults; `DependencyVia` gains `'fallback'` (`offlinePolicy: 'fallback-api'` → `anthropic-api`, `FALLBACK_RUNTIME`); `Dependents.workspaceWide` marks the active memory / learning plugin. State stays `v: 1`: `active` and `seenScopes` are optional, so earlier records read unchanged.
- Agent mentions activate (#222, CHT-06, COL-06): `createActorToolPorts().chat.post` starts one task per member the post explicitly MENTIONS — never `Chat.post`'s coordinator / sole-member fallback, so an agent's post without mentions wakes nobody — as the browser's `runActivation` does for a person: origin the message, objective its text, context the last 50 messages that member may read (`mentionContract`, `routing/mentions.ts`), the member's folder for the chat as `environmentId` + `workdir`, else the posting task's route environment when the assignee has no default (#220). Gated by the poster's `collaborators` (COL-10); each task is one level deeper than the posting task (`checkDepth`), so agents mentioning each other stop at `maxDepth`. The port answers `{ messageId, activated?: {agentId, taskId, status}[], notActivated?: {agentId, reason}[] }` and never un-posts.
- Delegated environment (#220): `Routing.run` resolves a delegated task's environment as the task's own, else the assignee's `defaultEnvironmentId`, else the delegating task's ROUTE environment — a chat-started parent carries its environment only on its route, so a coordinator delegating to a chat member without a default environment failed the child `no-environment` at once. The `environment.chosen` summary says `(the delegating task's)`; the `no-environment` message names the delegating task when there was one.
- Chat file access (#205, part of #203; CHT-04 / CHT-10 / MEM-11): `Chat.registerUpload(file)` records a pending upload for its uploader (users and external clients; `MAX_PENDING_UPLOADS` = 50 each, forgotten after `PENDING_TTL_MS` = 24 h). `Chat.post` validates every `agentic-file:` part — this chat, the caller's own pending upload or a file posted in a message the caller can see (re-share), the file's media type — and calls `ChatFileStore.markPosted` before storing; a Chat without a store refuses uploads and posts of pending uploads (501). `ChatState.files` indexes posted files through `applyChatEntry` (replays; outlives archiving). `Chat.fileAccess(fileId)` answers `ChatFile | null` by history visibility; session-event messages keep only files the agent can see. The router inlines a chat task's images for the target agent within `CHAT_FILE_INLINE_BUDGET` (the triggering message first, then the newest) and turns every other file into a note (`hydrateChatFiles`, `routing/files.ts`). `createActorToolPorts({ files })` serves `files.read` (text for text-like files, cut at `CHAT_FILE_TEXT_MAX_BYTES`; metadata otherwise) and `chat.post` attachments. The store is the optional `files` option of `defineChatActor` (new; `Chat` is its store-less default), `defineRoutingActor`, `createSessionFactory`, `createToolCallPort` and `defineWorkspace` (`deleteAll` calls `deleteChat` per chat). A chat-originated task is granted `chat_file_read` implicitly (`withChatFileRead` on the route's config, both paths) unless the agent's config names the tool itself (`ask` / `deny`).
- Session record under 2 MB (#198): a Durable Object value holds key + value up to 2 MB, and a long daemon turn's record reached 3 MB (the log, then the transcript). The record now keeps a window of the event log (`WINDOW_BYTES` 512 KB, `windowBytes` counted per event); past it the oldest ~`PAGE_BYTES` go to a write-once `SessionPage` actor (`session-page`, `{sessionKey}:p{n}`, not wire-callable) and a `roll` entry drops them from the window. `index` keeps what whole-history readers need (requests and decisions, turn boundaries, the calls requests ask about; `knownEvents`), so grants, `request(s)`, `resolution`, `resume` and learning never read a page; `events(from)` (now async), `tail(from)` and the turn-end transcript fold read the pages first — a follower overtaken by a roll between two snapshots too. `SessionInfo.eventCount` counts archived events. The stored transcript is bounded (`boundTranscript`, `TRANSCRIPT_BYTES` 1 MB: oldest tool outputs and reasoning first, then large arguments, then — as a last resort — the largest parts anywhere, each replaced by a marker; the events keep every byte). Pre-#198 records migrate in the reducer and roll down on their next append. Workspace export knows `session-page` (the session's `events()` already carries its content).
- Machine folder browsing (#189, EXE-06/08, OPS-03/04): `Machine.fsRequest(environmentId, op: FsOp)` → `{ requestId }` sends `fs.request` to the daemon (400 malformed op, 403 revoked, 404 unknown environment, 503 offline); the daemon's `fs.response` lands in state and `Machine.fsResult(requestId)` → `FsResultView { requestId, environmentId, op, status: pending | done | error, requestedAt, finishedAt?, result?, error? }` reads it (404 unknown), live-keyable by the string id. `list` is open to session drivers, `worktree` to the owner only. Pending requests fail `timeout` at their deadline through the `liveness` reminder (`MachinePorts.fsTimeoutMs`, default 30 s) and when the socket closes ("machine went offline"); at most `MAX_FS_REQUESTS` = 16 entries, oldest evicted first, finished ones pruned after `FS_RESULT_TTL_MS` = 2 min. New audit kind `workdir.worktree-created` `{ machineId, environmentId, repo, branch, path, base? }`, recorded once per successful worktree request under the owner who asked.
- Working folders end to end (#190, part of #185; EXE-06 / EXE-12 / OPS-03):
  - **Routing** resolves a task's folder once, in this order: the task's `workdir`; for a delegated task in its parent route's environment, the parent's folder; the agent's `execution.defaultWorkdir` in its `defaultEnvironmentId` only; else the environment's first `cwdRoots` entry. The folder is checked with core `pathWithin(cwd, env.cwdRoots, machine.os)` before any Session opens (a machine that never reported its OS counts as Windows). Outside the roots, the task fails `{ code: 'workdir-outside-roots', recoverable: false }` and `Machine.openSession` is never called. The folder is stored on the route (`Route.cwd`), in the `environment.chosen` audit data (`cwd`), on the Session record (`SessionOpenSpec.cwd`) and sent as `OpenSpec.cwd`, replacing the hard-coded `cwdRoots[0]`. On `anthropic-api` (and a `fallback-api`) a folder is ignored and recorded as `ignoredWorkdir`. A task's own `workdir` is noted on the Workspace over a one-way hop.
  - **Task:** `create` refuses a `workdir` without an `environmentId` with a 400. `Task.delegate` takes `workdir` and passes it into the child's contract, and the `delegate` tool's `environmentId` / `workdir` flow through `createActorToolPorts`.
  - **Chat:** `setWorkdir(agentId, ref | null)` is for members only (404 otherwise), and users and external clients only. It stores the ref on the member (`get().members[agentId].workdir`) and appends a visible note ("Working folder for … → … on …" / "… cleared"): a user `msg` carrying `workdir`, activating nobody.
  - **Schedule:** `ScheduleSpec.workdir` requires `environmentId` (400 otherwise); `update({ workdir: null })` clears it. The firing (`ScheduleFired.workdir`) carries it into the task's contract.
  - **Workspace:** `recentWorkdirs` holds at most `RECENT_WORKDIRS_MAX` = 20 entries, one per environment and path, most recent first. `noteWorkdir(ref)` updates it (owner only); `recentWorkdirs()` reads it.
- Coordination and persistence (#194): the router reads a chat task's roster (`Chat.get` + each member's config) into `SessionOpenSpec.roster` on both paths, and the daemon path's `system` is the full `buildSystemPrompt` (identity, instructions, the chat, the tools) — it was `instructions` alone. `delegate` refuses an assignee that is not a configured agent with `invalid` before a child task exists (it was a failed child with `agent-unconfigured`). On `@sigx/actors` 0.10 the Session declares `applyEntry: applySessionEntry` and `appendEntry` takes `ctx.append` — one O(entry) write per event on a storage with `appendText` (Durable Objects since signalxjs/actors#375), a full save compacting the log. `recordingStorage` forwards `appendText` and records `appends` (`TestActorApp.appends`) — it had dropped it, so every test ran the full-save path.
- Session (#194): `respond` fits a plain-string input answer to the request's form (`shapeAnswers`: the text answers every property, an array for a multi-select), so a client that sends one line of text to Claude Code's `AskUserQuestion` is never read as no answer. `recordUsage` skips a usage event with nothing billed (no cost, no token count besides `reasoningTokens` — Claude Code's thinking-token ticks): no Ledger row and no Task charge per streamed tick. `tail` and `resolution` follow the record through `ctx.changes({ throttleMs: 50 })`, so a follower clones the state at most every 50 ms instead of once per streamed event.
- `Machine.heartbeat()` refuses a revoked machine (#172, belt and braces behind the token check): 403 `machine … is revoked`, `online` stays `false`, the liveness reminder is not re-armed — the `heartbeat` frame was already refused at `socketMessage`.
- Memory delete (#149, MEM-05 / MEM-08): `Memory.delete(id)` — write access on the scope, saved inside the turn, `false` for an unknown id; `actorMemoryStore` passes it through, so the actor-backed plugin satisfies the new `MemoryStore.delete`.
- `task/task-index.ts` (#146): the `TaskIndex` actor — `{ws}:task-index`, one `TaskIndexRow` per task (status, wait, assignee, owner, origin kind, chat, parent, depth, environment, session, `createdAt`, `updatedAt`, `n`), `list({ status, assignee, parentId, limit })` newest first as the Tasks page's and Home's one live read, `size()`; `upsert` is hop-only (`methodAuthorize: never`) and forward-only by transition count; `trimIndex` caps the record at `TASK_INDEX_CAP` = 2000 by dropping the oldest settled rows. The Task actor writes its row through `indexTask(ctx, ws, state, at)` (`task/index-port.ts`) on `create`, after every `transition` and after a `wait` change — awaited in turn order, never failing the work (a host without the index runs tasks as before). `taskIndexKey`, `taskIndexRowOf`, `TASK_INDEX_TYPE`. Chosen over a `Workspace.tasks` id list: the pages need status and wait per row without a `Task.get` per id, and the Workspace record (settings, machines, pairing) should not take a write per task transition.
- Memories reach the model on the routed local path (#135, MEM-07 / LRN-05 / AC-09): `createSessionFactory` hands `spec.memories` (what `Session.open` retrieved) to `createPlatformModelAgent({ memories })`, so every request's system prompt carries the memory block; `Routing.placeLocal` and `placeRemote` open the session with the task's `objective` and `context`, so retrieval ranks on the task (`spec.retrieval.text` is the objective) and a correction's lesson names it. One rendering per path: `Session.open` appends the `## Platform memory` block to `spec.system` only when the caller built a system prompt (the daemon path); a local session records `spec.memories` and no `spec.system` — the factory's `buildSystemPrompt` is the one place the block is rendered there. `__tests__/routing/memories.test.ts`.
- Chat title (#124): `Chat.rename(title)` appends a `rename` entry (trimmed, at most `MAX_TITLE_LENGTH` = 120 characters; blank rejected; users and external clients only) and `Chat.get().title` carries the last one, absent until set; `Workspace.createChat({ title })` no longer ignores the title — it writes it to the new chat over a `ctx.actor` hop after the index save. `ChatState.title` folds through `applyChatEntry`, so it replays and exports like every other piece of chat state.
- Failure distinction and recovery (#46, #128; OPS-04 / OPS-05): the Routing actor tells a chat-originated task's chat about its failure — `fail(route, error)` and the turn-end `error` / `cancelled` settles publish a `task-failed` status (`ref` = task id, `error` = the `TaskError`; the Chat actor validates and folds the kind, `parseSessionEvent` requires both) so a thread never goes silent after a session that could not open (`session-open` / `no-api-key`), an offline environment, or an errored turn. `Session.resume(commandId?)`: a new prompt with the interrupted turn's input over the intact transcript (`interruptedTurn`, `resumeTurnId`, `resumeCommandId`; idempotent per interruption, `invalid` otherwise). `Routing.resume(taskId)`: the person's Resume — the session's `resume`, the task `waiting → active` with a `resumed: …` transition, the route back to `running` and followed on the `{turnId}:resume` turn. `RouteStatus` gains `interrupted`: an interrupted route parks there instead of staying `running` (which had `follow` re-following it in a loop). `__tests__/routing/recovery.test.ts`.
- Daemon policy (#121): `placeRemote` fills `OpenSpec.policy = { rules: config.approvalPolicy, grants: config.tools, constraints?: route.constraints }` so the daemon compiles the same session policy a local session runs under; `src/policy/compile.ts` moved to `@agentic/runtimes` (`packages/runtimes/src/policy`) and is re-exported here unchanged (`compilePolicy`, `grantPolicy`, `agentPolicy`, `constrainPolicy`, `sessionPolicy`, `ruleMatches`, plus `sessionPolicyOf`).
- `ask_user` (#122, COL-06 / CHT-09): `Session.raiseInput({ callId, message, toolName?, options? })` (the session's own agent only) appends a platform-raised `request { kind: 'input', requestId: 'ask:{callId}' }` once per call id, stamped by `platformCursor(head)` strictly between the head and the runtime's next `seq`; `respond` settles such a request itself (`SessionState.platformRequests`; input or cancel, a permission decision is `invalid`); the `resolution(requestId)` stream yields its `request-resolved`. `createActorToolPorts({ sessions })` / `createSessionFactory({ sessions })` implement `chat.ask` over it (the `answers` are the tool result via `answerText`, a cancel a `cancelled` tool error; `unsupported` without `sessions`); `createToolCallPort` passes its `sessions` through, so the daemon path is the same record. `appendEvent` now folds an event the log already has by nothing and notifies nobody twice (a replayed `request` frame no longer pushes a second Inbox row).
- Approvals (#40, OPS-02 / COL-10 / CHT-09): the Session is the one place a request is announced — `SessionPorts.inbox` (was `RoutingPorts.inbox`, which pushed only for routed task sessions): every `request` on either path becomes an `approval` / `input` Inbox notification with a session ref plus a chat status entry `request` (`ref` = `approval:{id}` | `input:{id}`), and its `request-resolved` marks the notification read (`Inbox.ackRef(ref)`, `sameRef`) and appends `request-resolved` with the same ref; `approval.requested` / `approval.resolved` audit events unchanged (once each). `Session.request(id)` / `requests({ openOnly })` — live reads (`reads`) returning `SessionRequestView`: the request, its call's input / category / annotations, the decision, the agent, chat and task, and the `approvalPolicy` rule that asked (`rule: 'ask on destructive'`); `SessionInfo.grants` lists session-scoped allows. `src/policy/requests.ts`: `requestRecordOf`, `requestRecordsOf`, `sessionGrantsOf`, `requestRef` / `parseRequestRef`, `permissionKeyOf`, `policyRequestOf`, `ruleFor`, `describeRule`. Grants are visible, not revocable — `@sigx/ai-agent` keeps a session's `SessionGrants` private and checks them before the policy; the daemon path's policy still waits for the rules to travel in the `OpenSpec` (#121). The Chat actor accepts the `request` / `request-resolved` status kinds.
- Routing (#106): AC-02 now routes two tasks to two environments of one machine concurrently — a regression test for the per-name single-flight `follow` that left the second route `running` (fixed by #39's follow supervisor).
- `audit/` (#44, platform half): `AuditActor` — `{ws}:audit` live log with `record(event)` idempotent by `event.key` (one `applyAuditEntry` entry, `ctx.append` where the runtime has it, else reducer + `ctx.save()`), `list({ kinds, agentId, taskId, sessionId, since, until, cursor, limit })` → `{ events, next }` newest first as a live `read`, `stats()`; the window (`AUDIT_WINDOW` 500) rolls its oldest `AUDIT_ROLL_BATCH` (100) into `{ws}:audit:{yyyy-mm}` UTC month archives through the idempotent `archive` hop, and `list` walks them by cursor. `AuditEventInput` / `AuditEvent` with the kinds `approval.requested/resolved`, `delegation.created`, `environment.chosen`, `task.transition`, `config.versioned`, `proposal.reviewed`, `machine.paired/revoked`, `plugin.enabled/disabled/granted`, `secret.opened` (`AUDIT_KINDS`, `assertAuditEvent`); `auditKey` / `auditMonthKey` / `auditMonth` / `parseAuditKey`; `AuditPort` + `auditPort()` (one-way, never fails a turn), `recordAudit(ctx, ws, event)`, `capturingAuditPort()`. Emitters, all one-way: Task (`transition`, `delegate` — the one `delegation.*` record, keyed `{taskKey}:child:{childId}`), Session (`appendEvent` after a permission `request` / `request-resolved` is durable; `SessionPorts.audit?`), Routing (`run` before placement and the `fallback-api` branch; `RoutingPorts.audit?`), Agent (`update` / `rollback` / `reviewProposal`), Machine (`pair`, first `revoke`), Registry (`enable` / `disable` / `grant` when they change something, `openSecret` every call). `apps/web` registers `AuditActor`.
- Delegation (#39): `createActorToolPorts().task.delegate` serves the `delegate` tool on both paths — collaborators check (`forbidden`), `Task.delegate` (`limit` / `invalid`), `Routing.run(child)` (a 409 for an already-routed or settled child is not an error), then the child's `result` stream; the same `callId` re-awaits the same child, and an aborted parent turn answers `cancelled` with `notStopped`. `src/policy`: `compilePolicy`, `grantPolicy`, `agentPolicy`, `constrainPolicy`, `sessionPolicy`, `ruleMatches`; `createSessionFactory` opens sessions under `sessionPolicy(spec)` (was `allowAll`). `SessionOpenSpec.approvalConstraints` and `Route.constraints`: a delegated task's session carries the approval rules of every ancestor's agent and is never wider (AC-12). `RoutingPorts.inbox`: a task session's `request` becomes an `approval` / `input` Inbox notification with a session ref. Routing `follow` is now one supervisor task following every running route (`ctx.tasks` is single-flight per name — before, a second concurrent route was never followed), cancels the session of a task settled from outside and sends `Task.sessionStopped` when the turn ends, and only resolves a `waiting {approval | input}` its own request parked (a policy decision's `request-resolved` no longer resumes a task `waiting {child}`). Task: a late `sessionStopped` or child acknowledgement after the cascade settled is re-acknowledged upward. `ask_user` stays `unsupported` (#40).

- Memory actor (#26): `Memory` keyed `{ws}:memory:{scope}` over the `@agentic/memory` core with `ctx.save()` per mutating turn; `memoryAuthorize` (same workspace; users and `memory`-scoped external clients own every scope; an agent reaches only `agent:{self}`; `shared:*` by a per-scope ACL checked in the turn — no ACL, no agent access); `memoryActorPlugin` / `actorMemoryStore` — the actor as a `MemoryPlugin` with paged export and batched import.

- Agent actor (#15): `AgentActor` keyed `{ws}:agent:{id}` with `get`, `update(patch, reason)`, `rollback(toVersion, reason?)`, `listVersions`, `snapshotForSession() → FrozenAgentConfig`; every version is one `{ t: 'config', v, patch, by, at, reason }` entry folded by the pure `applyAgentEntry` reducer and replayed for rollback; `agentKey`, `agentMemoryScope`, `defaultAgentConfig`, `mergeAgentConfig`, `principalLabel`.
- Session actor (#22): `defineSessionActor({ factory, commands })` keyed `{ws}:session:{id}` — every `AgentEvent` folded by the pure `applySessionEntry` reducer with one `ctx.save()` each (idempotent by `(epoch, seq)`; `EventLogStore` / `TranscriptStore` over the record), transcript snapshot at every turn end; `open` / `prompt` / `respond` / `cancel` / `configure` / `close` / `get` / `events` / `transcript`, idempotent by `commandId` across activations (capped at 256); `streams.tail(from)` replays then follows; the local turn runs in `tasks.drive`, and a turn cut short by an eviction ends as interrupted (`isInterruptedTurnEnd`), never re-run; daemon path through `forwardFrames` / `commandReplied` (only the hosting machine) and the `CommandSink` port; final assistant text and status published on `SESSION_EVENTS_TOPIC` to the session's chat.
- Chat actor (#16): `Chat` (`{ws}:chat:{id}`) with `post(input, mentions | 'all')` applying the §6 activation rule, `addAgent(id, 'all' | 'from-now')`, `removeAgent`, `setCoordinator`, `get`, `history(cursor, limit)` and `search(q)` filtered by the caller's `historyFrom`, a `session-events` subscription folding `SessionEvent`s into entries (malformed or unknown events are refused as delivery failures), and `ChatPage` archive actors (100 entries each) behind a 200-entry window so a post never rewrites the whole history. `applyChatEntry` is the pure reducer; `appendEntry` takes `ctx.append` when the runtime offers it.
- `task/`: the Task actor (`TaskActor`, keyed `{ws}:task:{id}`) — the `queued → active → (waiting ⇄ active) → completed | failed | cancelled` state machine with one log entry per transition (`from`, `to`, `by`, `why`, `wait`), `explain()` for the current `WaitReason`, `delegate(spec)` under depth / concurrency / budget-split limits with the deterministic child id `childTaskId(parent, callId)`, `tree()`, the `result` stream, and the `cancel` cascade that fans out one-way, waits for acknowledgements until a deadline and lists what could not be stopped (#17).
- `ledger/` (#45): `LedgerActor` keyed `{ws}:ledger:{yyyy-mm}` — `append(row)` idempotent by `row.key` (one `applyLedgerEntry` entry, `ctx.append` where the runtime has it, else reducer + `ctx.save()`), `rows(query)`, `summary({ by: 'agent' | 'task' | 'session' | 'turn' | 'day', timeZone? })` with `costUsd: null` for unreported data, the estimated share broken out and a `quality` flag (OPS-07), `recordCorrection` / `corrections` for LRN-09; pure `summarize`, `checkBudget` / `remainingBudget` / `budgetError` / `isBudgetFailure` (`BUDGET_ERROR_CODE = 'budget'`); `ledgerRecorder()` as the Session's new `usage` port and `ledgerCorrectionLedger`. Session: `SessionPorts.usage?` and `OpenedSession.usageRow?` — every turn-scoped `usage` event is priced, recorded one-way and charged to the task; a `failed {budget}` verdict cancels the running turn (locally, or through the `CommandSink`). Task: `recordUsage` and `delegate` check the budget — a task past `maxCostUsd` / `maxTokens` / `maxWallMs` ends `failed {budget}`, cancels its unsettled children one-way and creates no child (COL-11, OPS-08).
