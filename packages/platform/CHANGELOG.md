# Changelog

All notable changes to `@agentic/platform` (Keep a Changelog, semver).

## [Unreleased]

- Chat title (#124): `Chat.rename(title)` appends a `rename` entry (trimmed, at most `MAX_TITLE_LENGTH` = 120 characters; blank rejected; users and external clients only) and `Chat.get().title` carries the last one, absent until set; `Workspace.createChat({ title })` no longer ignores the title — it writes it to the new chat over a `ctx.actor` hop after the index save. `ChatState.title` folds through `applyChatEntry`, so it replays and exports like every other piece of chat state.
- Failure distinction and recovery (#46, #128; OPS-04 / OPS-05): the Routing actor tells a chat-originated task's chat about its failure — `fail(route, error)` and the turn-end `error` / `cancelled` settles publish a `task-failed` status (`ref` = task id, `error` = the `TaskError`; the Chat actor validates and folds the kind, `parseSessionEvent` requires both) so a thread never goes silent after a session that could not open (`session-open` / `no-api-key`), an offline environment, or an errored turn. `Session.resume(commandId?)`: a new prompt with the interrupted turn's input over the intact transcript (`interruptedTurn`, `resumeTurnId`, `resumeCommandId`; idempotent per interruption, `invalid` otherwise). `Routing.resume(taskId)`: the person's Resume — the session's `resume`, the task `waiting → active` with a `resumed: …` transition, the route back to `running` and followed on the `{turnId}:resume` turn. `RouteStatus` gains `interrupted`: an interrupted route parks there instead of staying `running` (which had `follow` re-following it in a loop). `__tests__/routing/recovery.test.ts`.
- Daemon policy (#121): `placeRemote` fills `OpenSpec.policy = { rules: config.approvalPolicy, grants: config.tools, constraints?: route.constraints }` so the daemon compiles the same session policy a local session runs under; `src/policy/compile.ts` moved to `@agentic/runtimes` (`packages/runtimes/src/policy`) and is re-exported here unchanged (`compilePolicy`, `grantPolicy`, `agentPolicy`, `constrainPolicy`, `sessionPolicy`, `ruleMatches`, plus `sessionPolicyOf`).
- `ask_user` (#122, COL-06 / CHT-09): `Session.raiseInput({ callId, message, toolName?, options? })` (the session's own agent only) appends a platform-raised `request { kind: 'input', requestId: 'ask:{callId}' }` once per call id, stamped by `platformCursor(head)` strictly between the head and the runtime's next `seq`; `respond` settles such a request itself (`SessionState.platformRequests`; input or cancel, a permission decision is `invalid`); the `resolution(requestId)` stream yields its `request-resolved`. `createActorToolPorts({ sessions })` / `createSessionFactory({ sessions })` implement `chat.ask` over it (the `answers` are the tool result via `answerText`, a cancel a `cancelled` tool error; `unsupported` without `sessions`); `createToolCallPort` passes its `sessions` through, so the daemon path is the same record. `appendEvent` now folds an event the log already has by nothing and notifies nobody twice (a replayed `request` frame no longer pushes a second Inbox row).
- Approvals (#40, OPS-02 / COL-10 / CHT-09): the Session is the one place a request is announced — `SessionPorts.inbox` (was `RoutingPorts.inbox`, which pushed only for routed task sessions): every `request` on either path becomes an `approval` / `input` Inbox notification with a session ref plus a chat status entry `request` (`ref` = `approval:{id}` | `input:{id}`), and its `request-resolved` marks the notification read (`Inbox.ackRef(ref)`, `sameRef`) and appends `request-resolved` with the same ref; `approval.requested` / `approval.resolved` audit events unchanged (once each). `Session.request(id)` / `requests({ openOnly })` — live reads (`reads`) returning `SessionRequestView`: the request, its call's input / category / annotations, the decision, the agent, chat and task, and the `approvalPolicy` rule that asked (`rule: 'ask on destructive'`); `SessionInfo.grants` lists session-scoped allows. `src/policy/requests.ts`: `requestRecordOf`, `requestRecordsOf`, `sessionGrantsOf`, `requestRef` / `parseRequestRef`, `permissionKeyOf`, `policyRequestOf`, `ruleFor`, `describeRule`. Grants are visible, not revocable — `@sigx/ai-agent` keeps a session's `SessionGrants` private and checks them before the policy; the daemon path's policy still waits for the rules to travel in the `OpenSpec` (#121). The Chat actor accepts the `request` / `request-resolved` status kinds.
- Routing (#106): AC-02 now routes two tasks to two environments of one machine concurrently — a regression test for the per-name single-flight `follow` that left the second route `running` (fixed by #39's follow supervisor).
- `audit/` (#44, platform half): `AuditActor` — `{ws}:audit` live log with `record(event)` idempotent by `event.key` (one `applyAuditEntry` entry, `ctx.append` where the runtime has it, else reducer + `ctx.save()`), `list({ kinds, agentId, taskId, sessionId, since, until, cursor, limit })` → `{ events, next }` newest first as a live `read`, `stats()`; the window (`AUDIT_WINDOW` 500) rolls its oldest `AUDIT_ROLL_BATCH` (100) into `{ws}:audit:{yyyy-mm}` UTC month archives through the idempotent `archive` hop, and `list` walks them by cursor. `AuditEventInput` / `AuditEvent` with the kinds `approval.requested/resolved`, `delegation.created`, `environment.chosen`, `task.transition`, `config.versioned`, `proposal.reviewed`, `machine.paired/revoked`, `plugin.enabled/disabled/granted`, `secret.opened` (`AUDIT_KINDS`, `assertAuditEvent`); `auditKey` / `auditMonthKey` / `auditMonth` / `parseAuditKey`; `AuditPort` + `auditPort()` (one-way, never fails a turn), `recordAudit(ctx, ws, event)`, `capturingAuditPort()`. Emitters, all one-way: Task (`transition`, `delegate` — the one `delegation.*` record, keyed `{taskKey}:child:{childId}`), Session (`appendEvent` after a permission `request` / `request-resolved` is durable; `SessionPorts.audit?`), Routing (`run` before placement and the `fallback-api` branch; `RoutingPorts.audit?`), Agent (`update` / `rollback` / `reviewProposal`), Machine (`pair`, first `revoke`), Registry (`enable` / `disable` / `grant` when they change something, `openSecret` every call). `apps/web` registers `AuditActor`.
- Delegation (#39): `createActorToolPorts().task.delegate` serves the `delegate` tool on both paths — collaborators check (`forbidden`), `Task.delegate` (`limit` / `invalid`), `Routing.run(child)` (a 409 for an already-routed or settled child is not an error), then the child's `result` stream; the same `callId` re-awaits the same child, and an aborted parent turn answers `cancelled` with `notStopped`. `src/policy`: `compilePolicy`, `grantPolicy`, `agentPolicy`, `constrainPolicy`, `sessionPolicy`, `ruleMatches`; `createSessionFactory` opens sessions under `sessionPolicy(spec)` (was `allowAll`). `SessionOpenSpec.approvalConstraints` and `Route.constraints`: a delegated task's session carries the approval rules of every ancestor's agent and is never wider (AC-12). `RoutingPorts.inbox`: a task session's `request` becomes an `approval` / `input` Inbox notification with a session ref. Routing `follow` is now one supervisor task following every running route (`ctx.tasks` is single-flight per name — before, a second concurrent route was never followed), cancels the session of a task settled from outside and sends `Task.sessionStopped` when the turn ends, and only resolves a `waiting {approval | input}` its own request parked (a policy decision's `request-resolved` no longer resumes a task `waiting {child}`). Task: a late `sessionStopped` or child acknowledgement after the cascade settled is re-acknowledged upward. `ask_user` stays `unsupported` (#40).
- Machine (#43): `doctor(environmentId?)` → `MachineDoctorView` — the per-environment `doctor` verdicts the daemon sent in `hello` / `env` (`EnvironmentDescriptor.doctor`: isolation and auth, EXE-05/07) with `ok` (every environment verified, none in error) and `unverified`; the stored `environments` now carry the verdict. AC-02 pinned in `__tests__/routing/routing.test.ts`: three accounts on one machine, each selectable, a run changes no other environment's account.
- `auth/oauth-server` (#50): the OAuth 2.1 authorization server for external MCP clients — `createOAuthServer({ secret, issuer, resource, store })` gives `metadata` (RFC 8414), `protectedResource` + `challenge` (RFC 9728), `register` (RFC 7591 DCR, public clients only), `authorize` (PKCE S256 required, exact-match redirect URI with the RFC 8252 loopback-port exception, scope validation against core's `Scope` union, consent HTML for a signed-in user with per-scope checkboxes, sealed `oatx` transaction bound to the user), `token` (authorization code single-use through the store, refresh tokens rotating on every use with replay → grant revocation, scope narrowing on refresh), `revoke` (RFC 7009) and `verify` (bearer → `{ kind: 'external', workspaceId, clientId, scopes }`, refused once the grant is revoked). Tokens: `oacd` code 10 min, `oaac` access 1 h, `oarf` refresh 30 d, all on the package `seal` envelope. `OAuthStore` port with `memoryOAuthStore()` and `actorOAuthStore()` over two new actors: `OAuthClients` (`global:oauth-clients`, anonymous `register` / `get`) and `OAuthGrants` (`{ws}:oauth:grants`, owner only, explicit `ctx.save()`). `ALL_SCOPES` / `parseScopes` / `isScope`.

- `schedule/trigger.ts` (#42): `scheduleTrigger({ environments?, onOutcome? })`, the platform's `TriggerPort` — a `reminder` entry (or any entry without an agent) becomes one Inbox notification of kind `reminder` pushed through every channel, from the entry's own alarm with no machine or browser online (AST-03/04, AC-08); an entry with an agent becomes a Task with `origin { kind: 'schedule' }`, id `scheduledTaskId(scheduleId, scheduledFor)` (exactly once per occurrence across the actor's retries), `queued`, or under the entry's offline policy when its environment is offline (`queue` / `fallback-api` → `waiting { environment-offline, policy }` for the router #37; `fail` → failed + `task-failed` notification); `EnvironmentProbe` is the seam the Machine actor's online status will fill (routing, #37), absent = everything offline. `deliverScheduleFired` exposes the same logic with its `ScheduleTriggerOutcome`. Seam change: `TriggerPort.fired(event, hop)` now receives a `TriggerHop` (the Schedule actor's `ctx.actor`), so ports hop without re-running `authorize` against a reminder's empty principal.
- Routing (#37): `defineRoutingActor({ sessions, machines })` keyed `{ws}:routing:main` — `run(taskId)` resolves runtime + environment once (never changed after, EXE-12), opens the Session locally (`anthropic-api`) or through `Machine.openSession` (`opened` → prompted on `sessionOpened`; `queued` → Task `waiting {capacity, position}`; offline → Task `waiting {environment-offline, policy}` and the agent's `queue` / `fail` / `fallback-api`, the last only when configured and always as a transition that says why), treats an environment no machine reports yet as offline under the same policy, fails a missing or mismatched environment with a code (`no-environment`, `runtime-mismatch`), adopts a task the schedule trigger parked `waiting {environment-offline}`, and settles the Task at the turn end through the `follow` task. `createEnvironmentProbe({ machines })` is the trigger's `EnvironmentProbe` over the Machines. `createSessionFactory` (the concrete `SessionFactory` over `createPlatformModelAgent`, BYO key), `createToolCallPort` (the Machine's `tool.call` over the same platform tool definitions) and `createActorToolPorts` (memory / chat / task_report under the agent principal; `delegate` / `ask_user` `unsupported` until #39). Machine: `MachinePorts.routing` and the one-way `machineOnline` / `sessionOpened` / `sessionClosed` notifications. Task: `reportWaiting` / `resolveWaiting` take an optional `sessionId`. `PairingDirectory` (`global:pairing`, single use, 10 min) filed by `Workspace.registerMachinePending` over a hop — register it wherever the Workspace runs. Depends on `@agentic/runtimes`.
- Machine actor (#36): `defineMachineActor({ socket, sessions, tools?, heartbeatWindowMs?, commandTimeoutMs? })` keyed `{ws}:machine:{id}` — `pair(code, info)` through `Workspace.claimPairing` (hash only, `tokenRecord()` for `serverAuth({ machines })`), `revoke`, `rename`, `get`; the daemon envelope over `socketMessage` / `socketClosed` (`hello` → `welcome {wanted}`, `env`, `heartbeat`, `session.opened` → wire `hello` to the Session, `session.frame` → `forwardFrames`, `session.reply` → `commandReplied`, `session.closed`, `tool.call` → `ToolCallPort` under the agent principal); `openSession` → `opened | queued` per environment concurrency, `closeSession`, `sendCommand` with pending replies and deadlines; the `liveness` reminder (offline after the heartbeat window, timed-out commands answered `internal`). `MachineSocketPort` / `ToolCallPort` / `ToolCallError`, `machineKey` / `parseMachineKey`, `toAgentCapabilities`. Depends on `@agentic/daemon-protocol` for the codec. `testing`: `testActorApp` takes a `scheduler`.
- Memory and learning on the execution path (#41): `task/driver.ts` — `retrieveMemories` (own + shared scopes as the agent principal, one limit/byte budget, refused scopes listed), `renderMemoryBlock` / `withMemoryBlock` (the platform-owned `## Platform memory` block), `taskOutcomeOf` / `verificationOf` / `turnStatusOf` (claimed vs verified, LRN-03), `correctionOf`, `instructionProposals`, `platformLearningPorts`; `defineSessionActor({ learning })` retrieves into `spec.memories` / `spec.retrieval` / `spec.system` at `open`, runs `plugin.onTaskEnd` at every regular turn end of a task session (`SessionInfo.learning`), and gains `correct(messageId, text, what)` → `plugin.onCorrection` as the agent (`SessionInfo.corrections`); `SessionOpenSpec` gains `objective`, `context`, `tags`, `memories`, `retrieval`. Agent actor: `propose` / `listProposals` / `reviewProposal` — instruction proposals wait for a user's review and land as a new, reversible config version (LRN-08); `AgentView.pendingProposals`.
- `registry/` (#48): the `Registry` actor (`{ws}:registry`, `defineRegistry({ kek })`) — plugins with manifest validation, `enable` / `disable` (returns `dependents`) / `remove` (refuses `plugin-in-use` unless forced), `configure`, `grant` / `revoke` limited to declared scopes (PLG-04), `dependents(id)` over the Workspace index + Agent configs + Schedules, `requireEnabled` helper throwing `PluginDisabledError` (AC-13), MCP connector records with probe status, secrets sealed under `WORKSPACE_KEK` and released only by `openSecret` to an enabled, granted plugin, `exportRows` (secret names only).
- `workspace/` (#48): `defineWorkspace({ sink, store })` — `exportAll` writes NDJSON per actor kind + `manifest.json` through the `ArtifactSink` port via each actor's `get` / `export` as the owner; `deleteAll` purges every child record through the `WorkspaceStore` port, then its own; progress in `get().ops`; `createSchedule` / `removeSchedule` index methods. `docs/retention.md` (OPS-10).

- Package skeleton.
- `auth`: `sameWorkspace` / `workspaceOwner` policies, `workspaceKey`, `workspaceOfActorKey` (#14).
- `workspace`: the `Workspace` root actor — owner, agent/chat/machine/schedule index, settings, pairing codes, `exportAll` / `deleteAll` task stubs (#14).
- `testing`: shared actor test harness — `testActorApp`, `recordingStorage`, `userPrincipal`, `statusOf` (#14).
- `notify` (#29): `NotificationChannel` seam, `Inbox` actor (`{ws}:inbox`; append / push / list / unread / ack / subscriptions, capped at 500, `authorize: [sameWorkspace]`), `deliverAll` recording a `DeliveryAttempt` per channel, and `webPushChannel` with VAPID ES256 over WebCrypto (contentless push; payload encryption is a follow-up).
- Memory actor (#26): `Memory` keyed `{ws}:memory:{scope}` over the `@agentic/memory` core with `ctx.save()` per mutating turn; `memoryAuthorize` (same workspace; users and `memory`-scoped external clients own every scope; an agent reaches only `agent:{self}`; `shared:*` by a per-scope ACL checked in the turn — no ACL, no agent access); `memoryActorPlugin` / `actorMemoryStore` — the actor as a `MemoryPlugin` with paged export and batched import.
- `auth` (#32): `AuthProvider` seam + `githubAuthProvider` over `fetch`; `__Host-session` cookie sealed with WebCrypto HMAC (`sealSession` / `openSession` / `sessionCookie`); provider-neutral `beginOAuth` / `completeOAuth` with state + PKCE S256 in a `__Host-oauth` transient; `principalCodec` / `encodePrincipal` / `decodePrincipal` for all four `Principal` kinds; `mintAgentPrincipal`, `sealAgentToken` / `openAgentToken` and `asPrincipal` for tool callbacks; machine pairing (`issuePairing` / `verifyPairing` / `consumePairing`, 6 chars, 10 min, single use) and machine tokens (`issueMachineToken` / `verifyMachineToken`, hash stored, revocation); `WORKSPACE_KEK` AES-GCM (`importWorkspaceKek` / `encryptSecret` / `decryptSecret`); `serverAuth()` → `{ authenticate, codec }` for `createServerApp`. The #14 policies moved to `auth/same-workspace.ts` (same exports).
- `schedule/`: `defineScheduleActor({trigger})` — `{ws}:schedule:{id}` actor with one-shot / cron-subset recurrence in an IANA zone, one-shot durable reminders re-armed per occurrence, `TriggerPort` / `ScheduleFired` outbound seam, `skip` catch-up policy with an in-state log, bounded retry of a failing port. Pure `recur.ts` (`parseCron`, `nextCron`, `resolveWallTime`, `nextOccurrence`, `countOccurrences`) on `Intl.DateTimeFormat` only; spring gap skipped, fall overlap fires the first occurrence (#28).
- Agent actor (#15): `AgentActor` keyed `{ws}:agent:{id}` with `get`, `update(patch, reason)`, `rollback(toVersion, reason?)`, `listVersions`, `snapshotForSession() → FrozenAgentConfig`; every version is one `{ t: 'config', v, patch, by, at, reason }` entry folded by the pure `applyAgentEntry` reducer and replayed for rollback; `agentKey`, `agentMemoryScope`, `defaultAgentConfig`, `mergeAgentConfig`, `principalLabel`.
- Session actor (#22): `defineSessionActor({ factory, commands })` keyed `{ws}:session:{id}` — every `AgentEvent` folded by the pure `applySessionEntry` reducer with one `ctx.save()` each (idempotent by `(epoch, seq)`; `EventLogStore` / `TranscriptStore` over the record), transcript snapshot at every turn end; `open` / `prompt` / `respond` / `cancel` / `configure` / `close` / `get` / `events` / `transcript`, idempotent by `commandId` across activations (capped at 256); `streams.tail(from)` replays then follows; the local turn runs in `tasks.drive`, and a turn cut short by an eviction ends as interrupted (`isInterruptedTurnEnd`), never re-run; daemon path through `forwardFrames` / `commandReplied` (only the hosting machine) and the `CommandSink` port; final assistant text and status published on `SESSION_EVENTS_TOPIC` to the session's chat.
- Chat actor (#16): `Chat` (`{ws}:chat:{id}`) with `post(input, mentions | 'all')` applying the §6 activation rule, `addAgent(id, 'all' | 'from-now')`, `removeAgent`, `setCoordinator`, `get`, `history(cursor, limit)` and `search(q)` filtered by the caller's `historyFrom`, a `session-events` subscription folding `SessionEvent`s into entries (malformed or unknown events are refused as delivery failures), and `ChatPage` archive actors (100 entries each) behind a 200-entry window so a post never rewrites the whole history. `applyChatEntry` is the pure reducer; `appendEntry` takes `ctx.append` when the runtime offers it.
- `task/`: the Task actor (`TaskActor`, keyed `{ws}:task:{id}`) — the `queued → active → (waiting ⇄ active) → completed | failed | cancelled` state machine with one log entry per transition (`from`, `to`, `by`, `why`, `wait`), `explain()` for the current `WaitReason`, `delegate(spec)` under depth / concurrency / budget-split limits with the deterministic child id `childTaskId(parent, callId)`, `tree()`, the `result` stream, and the `cancel` cascade that fans out one-way, waits for acknowledgements until a deadline and lists what could not be stopped (#17).
- `ledger/` (#45): `LedgerActor` keyed `{ws}:ledger:{yyyy-mm}` — `append(row)` idempotent by `row.key` (one `applyLedgerEntry` entry, `ctx.append` where the runtime has it, else reducer + `ctx.save()`), `rows(query)`, `summary({ by: 'agent' | 'task' | 'session' | 'turn' | 'day', timeZone? })` with `costUsd: null` for unreported data, the estimated share broken out and a `quality` flag (OPS-07), `recordCorrection` / `corrections` for LRN-09; pure `summarize`, `checkBudget` / `remainingBudget` / `budgetError` / `isBudgetFailure` (`BUDGET_ERROR_CODE = 'budget'`); `ledgerRecorder()` as the Session's new `usage` port and `ledgerCorrectionLedger`. Session: `SessionPorts.usage?` and `OpenedSession.usageRow?` — every turn-scoped `usage` event is priced, recorded one-way and charged to the task; a `failed {budget}` verdict cancels the running turn (locally, or through the `CommandSink`). Task: `recordUsage` and `delegate` check the budget — a task past `maxCostUsd` / `maxTokens` / `maxWallMs` ends `failed {budget}`, cancels its unsettled children one-way and creates no child (COL-11, OPS-08).
