# Changelog

All notable changes to `@agentic/web` (Keep a Changelog, semver).

## [Unreleased]

- Chat titles (#124): `chatTitle(members, lookup, title?)` prefers the title the Chat actor stores (`Chat.get().title`) over the members' names, so the chat list rows and the topbar crumb / app-bar title show a named chat by its name; `entryLine` lines a `rename` entry ("Renamed to …"). The tsx live-page tests (`apps/*/__tests__/**/*.tsx`) are now in `tsconfig.json`'s `include`, so `pnpm typecheck` covers the live harness.
- Mobile Home heading (#118, `docs/design/HANDOFF.md` → "Mobile specifics"): below 768 px the "Needs you · N open" heading stays on one line (`white-space: nowrap` on the `h2`) and its hint ("answer here, in the chat, or on your phone") is dropped; `e2e/mobile.spec.ts` asserts the heading is one line box high with the count beside it and the hint hidden.
- Failure distinction and recovery (#46, #128; OPS-04 / OPS-05): `src/components/status/` — `failureOf(signals)`, the one pure mapping from the live signals (this browser's socket, `Machine.online`, the environment's `authStatus` / doctor verdict, the session's state and last adapter error, `Task.status` / `error.code`, the interrupted marker) to exactly one of the design track's named `FailureCard` states — `client-offline`, `machine`, `auth`, `runtime`, `task`, `interrupted` (uncertain) — by the reader's precedence (the socket, the machine, the account, an interruption, the runtime, the task); `taskFailureKind` maps the router's and the adapter's error codes. `clientConnection` is the socket signal: `watchTransport` wraps the actor transport (frames and answers say `live`, a dropped `$live` stream or a network failure `reconnecting`), `installClientConnection` adds the browser's `online` / `offline`; the entry installs both. `FailureNotice` renders a state on `FailureCard` with the one action wired (`Open task` / `Open machine` links, `Resume` / `Retry turn` / `Re-check` callbacks, the offline card's disabled `Reconnecting…`) and the OPS-05 uncertainty line under an interrupted card. `LiveConnection` is the shell's connection strip in live mode (this browser, then every paired machine by `Machine.online` with its session count; `Machine` joins `ActorDefs`); the `OfflineBanner` shows while reconnecting; mock mode draws the same `ConnectionStrip` over the design workspace. Chat (`chatFailure`): a feed's transcript (interrupted, errored) or the newest `task-failed` / `interrupted:` status since the user last posted becomes the card under the thread — `Resume` is `Routing.resume(taskId)` (the feed records its `taskId`), `Retry turn` re-posts the last message; a `session-open` failure such as `no-api-key` is a `task-failed` row and the "Task failed" card (#128). Session page: `sessionSignals(view)` → the card above the log; `LiveSession` reads the daemon session's `Machine` live for `online` and the account's `authStatus`, and Resume goes to the router (or `Session.resume` for a task-less session). Task page: `pages/task/LiveTask.tsx` reads `Task.get` / `tree` live in `live` mode — the delegation nodes, contract, transitions and result — with the failure card, `interrupted · uncertain` on the node, the resume wait in the transitions and Resume; the mock page shows the selected node's card. Tests: `__tests__/pages/failure.test.tsx` (the mapper per state, the transport watcher, the session page per state over fake signals, the strip over a paired machine going online / offline, the chat's #128 row, an adapter error, an evicted turn resumed from the card, the task page resumed); the live harness takes a `factory` override and hosts the Machine actor, and its `until` awaits async checks.
- Approvals (#40): `src/pages/inbox/` — "Needs you" as `NeedsYou` over a `NeedsSource` (`useNeedsSource`, an injectable whose default is the mock workspace): `liveNeedsSource(defs, workspaceId)` reads the Inbox `list` and each row's `Session.request(id)` as `useActorState` live reads and answers through `Session.respond` (`once` | `session` from the `ai-approval` card, `{ type: 'input' }` from the answer box), so a decision from any client drops the row and collapses the card everywhere; `memoryNeedsSource` is the same contract in memory (the mock, the tests). - OAuth 2.1 server + MCP mount for external clients (#50, `src/auth/oauth-server`): `createOAuthRoutes(env, { actors })` mounts `GET /.well-known/oauth-authorization-server`, `GET /.well-known/oauth-protected-resource[/_agentic/mcp]`, `POST /oauth/register`, `GET|POST /oauth/authorize` (consent keyed by the `__Host-session` cookie; anonymous → `/auth/login?returnTo=…`), `POST /oauth/token`, `POST /oauth/revoke`, and the platform MCP server on every method of `/_agentic/mcp` with bearer = the access token — wired in `entry.cloudflare.ts` next to the auth routes (same `SESSION_SECRET` / `APP_ORIGIN`). `createActorPlatformPort(principal, { actors })` is the real `PlatformPort`: a fresh `actor()` call per capability under the external principal, the Workspace index read and `Routing.run` as the workspace's user; `sessions_open` checks the named machine reports the named environment before `Task.create` (`origin { kind: 'external', clientId }`) + `Routing.run`; `tasks_delegate` is `Task.delegate` on the parent under the external principal + `Routing.run` on the child as the driver (a repeated `callId` re-finds the child); `environments_doctor` is `Machine.doctor`. `platformActors()` registers `OAuthClients` and `OAuthGrants`; `platformRegistry()` exposes the isolate's registry. `claude mcp add --transport http agentic https://<origin>/_agentic/mcp` needs no manual token.
