# Architecture — Unified Agent Platform

Status: v1 design, 2026-09-17. Requirements: [`requirements.md`](requirements.md). Decisions: [`decisions.md`](decisions.md). Promotion candidates: [`promotion.md`](promotion.md).

Every sub-issue of the tracking issue names the section here it implements. A section is the contract an implementing agent works to; change the section in the same PR when a seam changes.

## 1. Package layout

pnpm monorepo, `@agentic/*`, all private.

```
apps/web               sigx SSR + serverFn + actors host on Cloudflare (Worker + ActorHost Durable Object in one bundle); UI on @sigx/zero + zero-daisyui
apps/daemon            Node 22 bin `agentic-daemon` (pair | run | doctor); Windows first
packages/core          edge-safe types + tiny helpers, zero deps: ids, AgentConfig, ChatEntry, TaskState/WaitReason/TaskContract, EnvironmentDescriptor, CapabilityReport, PluginManifest, MemoryPlugin/LearningPlugin interfaces, daemon frame types, Principal kinds
packages/platform      defineActor definitions + services: Workspace, Agent, Chat, Task, Session, Machine, Schedule, Memory, Inbox, Ledger, Registry, Audit; auth helpers
packages/runtimes      runtime adapters: 'anthropic-api' (modelAgent), 'claude-code' (daemon driver); platform tools (memory.*, delegate, chat.post, task.report, ask_user)
packages/memory        default MemoryPlugin (Memory-actor backed, BM25-ish + recency, no embeddings) + memoryConformance
packages/learning      default LearningPlugin (corrections → lessons; proposals needing review)
packages/daemon-protocol  envelope validators + daemonConformance (types live in core)
packages/ui            @agentic/ui: zero fragment (ai-thread, ai-message, ai-composer, ai-tool-call, ai-reasoning, ai-approval) + layout shell (Stack/Row/Col on data-l-*) + StreamingMarkdown on @sigx/markdown
packages/mcp           MCP client (Streamable HTTP, edge-safe; stdio on the daemon) + platform MCP server (orchestration surface)
packages/a2a           A2A 1.0 JSON-RPC server (agent card + tasks) + client adapter implementing the @sigx/ai-agent Agent contract
```

Rules:

- `packages/*` never import the `sigx` umbrella (it drags `@sigx/runtime-dom/platform`). Peer on `@sigx/runtime-core` / `@sigx/reactivity` / `@sigx/actors` only, so packages stay edge-safe and renderer-neutral. Only `apps/web` and `packages/ui` touch the DOM.
- Import order (downward only): core ← daemon-protocol ← memory / learning ← runtimes ← platform ← apps.
- Source layout as in signalxjs/ai: one folder per concern, `index.ts` is the public surface, entry points are folders.
- Every sigx-estate version comes from the `catalog:` in `pnpm-workspace.yaml`.

## 3. Hosting topology

- One Cloudflare Worker (`apps/web`) serves SSR pages, serverFns, static assets, the actor HTTP mount (`/_sigx/actor`), the browser live socket (`createWorkerHandler({socket: {terminate: 'object'}})`), the daemon socket (`/_agentic/daemon/{machineId}`, accepted by the Machine Durable Object), MCP (`/_agentic/mcp`), A2A (`/_agentic/a2a/{agentId}` and `/.well-known/agent-card.json`), webhooks (`/_agentic/hooks/{id}`), OAuth callbacks.
- One Durable Object namespace `ACTORS`, one object per actor, SQLite-backed (`migrations: [{tag: 'v1', new_sqlite_classes: ['ActorHost']}]` — never `new_classes`, it is irreversible), `durableObjectStorage()` + `durableObjectReminders()` (alarms). `wrangler.jsonc` needs `compatibility_flags: ["nodejs_compat"]` and `define: {"__DEV__": "false"}`.
- **Eviction is not deactivation.** `onDeactivate` never runs on Workers. Every mutation ends in `ctx.save()` or `ctx.append()` inside the turn.
- R2 bucket for artifacts and exports. Workers Secrets for the OAuth client secret, `WORKSPACE_KEK` (AES-GCM key for stored API keys), VAPID keys later. No D1 in v1.
- Implementation (#33): `apps/web/src/actors.app.ts` holds the registry (`platformActors(ports)`), `createActorHost()` (the `ActorHost` class; `createHostDurableObject` derives storage and reminders from the object's own state, `socket: {}` accepts object-terminated sockets) and `createActorWorker({ fallback })` (the Worker half; server functions and SSR are its fallback). Both halves call `ensureServerApp(env)` first — `createServerApp({ ...serverAuth({ sessionSecret }) })` — so `authorize` sees the same principal in the Worker and after the hop into the object. No `SESSION_SECRET` → every caller is anonymous, never a fallback secret. Ports not wired yet refuse loudly: the Session `factory` returns `null` (daemon path) until #35, the platform `tools` a daemon session calls back are answered `unsupported` until #37. The Schedule trigger is the platform's `scheduleTrigger()` (#42; §4 Schedule) with no environment probe wired yet, so a scheduled task that needs an environment waits `environment-offline` for the router (#37). Routing order in `entry.cloudflare.ts`: auth routes → the actor worker (`/_agentic/daemon/{machineId}` forwarded to the Machine object, actor mount, actor sockets) → server functions → document. `test:workers` (`@cloudflare/vitest-pool-workers`) drives the real object on SQLite storage; deploy steps are in `docs/runbook.md`.
- Follow-up, not v1: split the DO host into a second Worker so UI deploys cannot evict live sessions.

### Audit

`packages/platform/src/audit` (issue #44, the platform half; the `/history` page is the UI track's). Every consequential action is one `AuditEvent` — `{ key, seq, kind, at, by, summary, agentId?, taskId?, sessionId?, data }` — recorded ONCE per occurrence by the actor that performs it, through `recordAudit(ctx, workspaceId, event)` (or the `AuditPort` the Session and Routing actors take in their ports; `auditPort()` is the default, `capturingAuditPort()` the test double). The helper is a ONE-WAY hop to `{ws}:audit`: it resolves at acceptance and swallows every failure, so the history never stalls or fails the turn that did the work. Idempotency is the emitter's: `key` derives from the source record (`{taskKey}:transition:{n}`, `{sessionKey}:{epoch}:{seq}`, `{agentKey}:v{n}`, `{machineKey}:paired`, …), so a retried turn or a replayed frame folds once. `by` is `user:|agent:|machine:|external:<id>` or `system:<name>` (`system:routing`, `system:policy`).

**Keys.** `{ws}:audit` is the live log: `record` stamps each event with the next `seq` and keeps the newest `AUDIT_WINDOW` (500) in state; once the window holds `AUDIT_WINDOW + AUDIT_ROLL_BATCH` events the oldest batch (100) rolls over into `{ws}:audit:{yyyy-mm}` archives — one per UTC month of the event's `at`, written through an idempotent `archive` hop (like Chat's pages; a crash between the hop and the save repeats it) — so a workspace's history never rewrites one ever-growing record and a month can be retained or dropped as a unit. The window-plus-monthly-archive shape was chosen over one actor per month (the Ledger's) because the history page wants ONE live entry point and one cursor: `list(query)` on the live key is a `read` (`useActorState(AuditActor, auditKey(ws)).list(q)` re-runs after every record), newest first, and walks the archives itself when the cursor passes the window (newest month first; `since` / `until` prune the months it cannot match). `list({ kinds?, agentId?, taskId?, sessionId?, since? (inclusive), until? (exclusive), cursor? (exclusive seq, `null` = newest), limit? (≤ 200) })` → `{ events, next }`, `next` being the seq to pass back or `null` when nothing older can match; `taskId` also matches a `delegation.created` by its child. `stats()` reports `inState`, `recorded`, `archived`, `months`. Over the wire only a user records; `archive` is never wire-callable — hops run no policy.

### Schedule

`packages/platform/src/schedule` (issue #28). One actor per entry, keyed `{ws}:schedule:{id}`, `defineScheduleActor({trigger: TriggerPort})`. Recurrence is `{kind: 'at', at}` (one-shot, epoch ms) or `{kind: 'cron', cron, tz}` — a 5-field cron subset (`*`, `n`, `a-b`, `a,b`, `*/n`, `a-b/n`; no names, no `L`/`W`/`#`) evaluated on the wall clock of an IANA zone. `next` is computed in `recur.ts` from `Intl.DateTimeFormat` parts only (no dependency, edge-safe); an unknown zone or bad expression is rejected at `create`/`update`, never stored.

Each occurrence is armed as a ONE-SHOT reminder (`ctx.reminders.set('fire', {due: next - now})`), re-armed from `onReminder` — the runtime's 60 s period floor is never requested, and on Cloudflare the entry's own alarm fires it with no machine or browser online (AST-03/04). `onReminder` posts a `ScheduleFired {workspaceId, scheduleId, key, kind, title, scheduledFor, firedAt, occurrence, skipped, agentId?, environmentId?, prompt?, offlinePolicy}` to the `TriggerPort` together with a `TriggerHop` (the actor's own `ctx.actor`, so the port reaches other actors as trusted hops — a reminder runs with no principal, and an in-process `actor()` from the port would be refused by `sameWorkspace`), then re-arms. A rejecting port is retried one floor (60 s) later up to 3 attempts, then the occurrence is logged `dropped` and the calendar moves on. Every mutation ends in `ctx.save()` inside the turn.

**Trigger (#42)** — `scheduleTrigger({environments?})` in `schedule/trigger.ts` is the platform's port, registered by `apps/web/src/actors.app.ts`. A `reminder` entry, or any entry without an `agentId`, becomes one Inbox notification of kind `reminder` (`body` = the prompt, `ref {kind: 'schedule'}`) through `Inbox.push`, so every configured channel delivers it from the entry's own alarm (AST-04, AC-08). An entry with an agent becomes a Task owned by and assigned to that agent, `origin {kind: 'schedule', scheduleId}`, objective = prompt (title when absent), with the id `scheduledTaskId(scheduleId, scheduledFor)` — deterministic and `Task.create` idempotent, so the actor's retry of a firing that threw half-way finds the task it already routed (exactly once per occurrence). AST-05: with an `environmentId` the trigger asks the `EnvironmentProbe` (the Machine actor's seam, #36; absent = every environment is offline). Offline under `queue` or `fallback-api` → `reportWaiting({kind: 'environment-offline', environmentId, policy})` — recorded for the router (#37) to resolve, never routed here; under `fail` → `fail({code: 'environment-offline'})` plus a `task-failed` notification. Online, or no environment → the task stays `queued`.

**DST rules (AST-07)**, fixtures in `__tests__/schedule/recur.test.ts` for Europe/Stockholm 2026:

- *Spring gap* — a wall time that does not exist (02:30 on 29 Mar, when 02:00 CET → 03:00 CEST) is skipped; `30 2 * * *` fires 28 Mar 01:30Z, then 30 Mar 00:30Z.
- *Fall overlap* — a wall time that exists twice (02:30 on 25 Oct, when 03:00 CEST → 02:00 CET) fires on its FIRST occurrence only (the CEST instant, 00:30Z); the repeated hour never fires a second time, whatever the minute pattern, so `*/30 * * * *` goes 00:30Z → 02:00Z that morning.
- *Catch-up policy `skip`* — a reminder that runs late (host down, alarm delayed) fires once for the occurrence it was armed for with `skipped = ` the number of later occurrences that fell before "now", writes a `skipped` log entry, and re-arms strictly after "now". Never a burst.
- Reminders are "at or after due" with the host's tick as resolution (60 s on the sharded table; exact on DO alarms); an entry due sooner than a tick fires on the next tick, never early.

## 5. Session execution paths

### 5a. Platform-managed API agent (`anthropic-api`)

The Session actor is built once per app over its ports (`packages/platform/src/session/ports.ts`): `defineSessionActor({ factory, commands })`. The `SessionFactory` maps a runtime id to an `OpenedSession` (`{ session: AgentSession, agentId, capabilities }`) or `null` for a daemon-hosted runtime; `@agentic/runtimes` supplies the `modelAgent` one, tests plug `mockAgent`. The actor never imports an adapter.

```ts
// open: record the spec, open the runtime session (resume from the recorded ref), serve it in-process
const opened = await factory(spec.runtime, { spec, resume: state.ref, signal: ctx.abortSignal, transcripts });
const served = serveSession(opened.session, { agentId, capabilities });   // command validation, busy/closed, one reply per commandId
// prompt: idempotent by commandId (persisted), then the turn runs as a detached task
const reply = await served.handleCommand({ v: 1, commandId, type: 'prompt', turnId, input });
if (reply.kind === 'ack') { state.running = { turnId, commandId, input }; await ctx.tasks.start('drive', { turnId }); }
// drive: subscribe from the durable head, one turn per event, until this turn's turn-end
for await (const ev of session.subscribe(state.head)) await ctx.turn((c) => appendEntry(c, { t: 'ev', ev }));
```

- `createPlatformModelAgent(cfg, { ports, anthropic: { apiKey }, store, skills, memories })` (`packages/runtimes/src/anthropic`) builds that `agent`: the roster is the platform tools the config grants (`deny` and skills never add one, AGT-04), `system` is assembled stable-first (identity, role, instructions, skills, tools, then the memory block), `pricing` is the `claude-*` table with `estimated: true` for an unlisted id, and it returns a `CapabilityReport` (AGT-09) plus `usageRow(event, …)` for the Ledger. Platform tools are `defineTool`s over abstract ports (`MemoryPort`, `TaskPort`, `ChatPort` in `packages/runtimes/src/tools/ports.ts`) the Session supplies under the agent principal; on the wire they are `memory_search`, `memory_remember`, `delegate`, `chat_post`, `task_report`, `ask_user` (provider tool names allow `[A-Za-z0-9_-]` only). `ask_user` goes through `ChatPort.ask` — the engine never raises an input `request` itself.
- Every event is durable before the next is read; the reducer (`applySessionEntry`) is pure and idempotent by `(epoch, seq)`, so a frame replayed twice folds once. At a turn end the driver folds the new events into the transcript snapshot, refreshes `ref`, publishes the final assistant text on `SESSION_EVENTS_TOPIC` keyed by the chat's actor key, and saves.
- Eviction mid-turn loses nothing already saved. The runtime's task ledger restarts `drive({ turnId })` on the next activation; it finds no live session for that turn and closes it honestly: `tool-update cancelled` for calls still open, `request-resolved {outcome: cancel}` for open requests, `error {code: 'process_exited', recoverable: true, data: {interrupted: true}}`, `state idle`, then `turn-end {stopReason: 'error'}` — `isInterruptedTurnEnd(ev)` names it. The Task driver reads that and marks the Task `waiting {input}` with "Resume?". A model call is never replayed (OPS-05/06). A live session opened afterwards resumes from `ref` in a new epoch, so the log stays gapless per epoch.
- Approvals: `request` event → Task `waiting {approval}` + Inbox notification + Chat status entry → user responds → `Session.respond` reaches the live `AgentSession`. A decision that arrives after an interruption is a no-op ack: the interrupted turn is closed, not resumed.
- `tail(from)` replays the log from `from` (exclusive) out of a state snapshot, then follows `ctx.changes()` until the session closes; `{ epoch: 0, seq: 0 }` gives a late joiner the whole log, and reducing it equals the driver's snapshot.
- Limits `{maxTurns, maxSteps, maxTokens, maxCostUsd, maxWallMs, maxDepth, maxConcurrentChildren}` enforced in the driver; every `usage` event → Ledger (estimated flag when pricing is unknown). As implemented (#45, `packages/platform/src/ledger`): `defineSessionActor({ factory, usage: ledgerRecorder() })` — after each **turn-scoped** `usage` event is durable (session-scoped events are cumulative totals, never counted) the driver prices the row with the `OpenedSession.usageRow` the factory returned (`createPlatformModelAgent(...).usageRow`; `estimated: true` for an unlisted model), else records the event's own `costUsd` as reported, else an unpriced row (provider data unavailable); the row's `key` is `{sessionId}:{epoch}:{seq}` so a replay folds once. `ledgerRecorder` appends it to `{ws}:ledger:{yyyy-mm}` one-way (the books never stall a turn) and, when the session works a task, charges `Task.recordUsage`; a `failed {budget}` task comes back as the verdict and the driver cancels the running turn — on the served session locally, through the `CommandSink` on the daemon path. `maxCostUsd`, `maxTokens` and `maxWallMs` are what the Task can measure today; `maxTurns` / `maxSteps` are runtime-side (`modelAgent({ maxSteps })`, `claudeCode({ maxTurns })`).
- API keys are user-provided (BYO), encrypted in Registry with `WORKSPACE_KEK`.

### 5b. Daemon-hosted Claude Code

The daemon runs one `claudeCode({ settingSources: [], env: { CLAUDE_CONFIG_DIR: env.profileDir }, models })` per environment. Sessions open with `cwd` from `cwdRoots`, `system` = instructions + skills + retrieved memory block with `systemPromptPreset: true`, `maxTurns` / `maxBudgetUsd` from limits, policy compiled from the agent's approval rules. Per session: `serveSession(claudeSession, { agentId, capabilities, eventLog: diskLog })` and pump `served.events(from)` upward.

**One hibernatable WebSocket** from the daemon to its Machine DO carries the daemon-protocol envelope (types in `@agentic/core` as `DaemonFrame<F, R>` / `PlatformFrame<C>`, generic over the `@sigx/ai-agent/wire` frame, reply and command types so core stays dependency-free; `@agentic/daemon-protocol` instantiates and validates them):

```
daemon → platform: hello {machineId, daemonVersion, os, environments[], capabilities[], resume: {sessionId → cursor}}
                   env {environments[]} · heartbeat · session.opened {sessionId, ref, capabilities, head}
                   session.frame {sessionId, frame: WireFrame} · session.reply {sessionId, reply} · session.closed {sessionId, reason}
                   tool.call {callId, sessionId, tool, input} · pong
platform → daemon: welcome {serverTime, wanted: {sessionId → cursor}} · session.open {sessionId, environmentId, spec}
                   session.command {sessionId, command: WireCommand} · session.close {sessionId}
                   tool.result {callId, exactly one of output | error} · ping
```

- Machine DO routes `session.frame` → `actor(Session, id).forwardFrames(frames)` (one-way; `hello` records ref + capabilities, `event` folds, `gap` marks `disconnected` and moves the head); `session.reply` → `Session.commandReplied` (a prompt ack marks the turn running, its `turn-end` frame snapshots the transcript and posts to the chat); `tool.call` → the platform tool under an **agent principal** `{kind: 'agent', ws, agentId, sessionId, taskId}` so Memory/Task authorize correctly.
- Session → daemon: `Session.prompt` records the command as pending (idempotent while the reply is out) and hands it to the `CommandSink` port — the app binds it to `actor(Machine).sendCommand(sessionId, cmd)` → socket. Pending replies are stored in Machine state with a deadline so evictions do not leak promises.
- Reconnect: the daemon redials with backoff; `welcome.wanted` cursors drive gapless replay from the daemon's per-session NDJSON log (`%LOCALAPPDATA%/agentic/sessions/{id}.ndjson`); beyond that a `gap` marks the Session `disconnected` with "events lost" (OPS-04, distinct from failure).
- **Driver seam** (`@agentic/core` `RuntimeDriver<S, P>`): the daemon reads `LocalEnvironment` rows from `environments.json`, asks the driver to `inspect(env)` (auth status, isolation, `CapabilityReport`) and runs its `doctor(envs)` for `hello` / `env` via `toEnvironmentDescriptor` (the per-environment verdict `EnvironmentDescriptor.doctor = environmentVerdict(report, id, checkedAt)`; a throwing driver gives each of its environments an error verdict `driver-doctor-failed`), `open(env, OpenSpec, { sessionId, callTool, policy })` → `{ session, capabilities }` on `session.open`, and runs `doctor(envs)` for `agentic-daemon doctor`. `callTool` is how a driver's platform tools reach the socket as `tool.call`. The daemon never branches on the runtime id; it picks the driver whose `runtime` matches the row.
- Multi-account isolation = `CLAUDE_CONFIG_DIR` per environment (the adapter's env allowlist passes it through). `claudeCodeDriver` (`@agentic/runtimes/claude-code`, #20) sets it from `profileDir` and removes the daemon's own `CLAUDE_CONFIG_DIR` and `ANTHROPIC_*` from every child, so an environment can only ever use its own account; `inspect` reads auth status from `<config dir>/.credentials.json`; the memory block reaches Claude Code as `## Platform memory` and the `CapabilityReport` lists `memory.runtime` (CLAUDE.md, settings — not loaded, `settingSources: []`) as unsupported (MEM-10). macOS Keychain behaviour is unverified, so v1 validates Windows only; `doctor()` implements EXE-07 with the codes in `CLAUDE_CODE_DOCTOR_CODES` (`shared-config-dir` is the error). Isolation is pinned by `packages/runtimes/__tests__/claude-code/isolation.test.ts` (three profiles: every child env equal to the others except its own `CLAUDE_CONFIG_DIR`, a session in one profile changing nothing about another, a shared config dir refused and its verdict failing exactly the two) and AC-02 by the routing test "multi-account environments on one machine" (three environments selectable through Routing, every `session.open` naming the chosen one, accounts and verdicts untouched by execution); `docs/multi-account.md` has the mechanism, the verified / unverified matrix and the manual checklist for the real CLI (#43).
- Platform tools reach Claude Code through the adapter's local MCP tool server; their `execute` sends `tool.call` over the same socket and awaits `tool.result`.
- **Daemon** (`apps/daemon`, #19): `agentic-daemon pair <code> --url` posts to `POST /auth/pair` and stores `{url, workspaceId, machineId, token}` in `%APPDATA%/agentic/credentials.json`, owner-only (`icacls /inheritance:r /grant:r user:F` before the token is written; `0600` elsewhere). `run` dials `/_agentic/daemon/{machineId}` with `Authorization: Bearer <token>` (never in the URL), redialling with exponential backoff and jitter; every log line is redacted of the token. The session log is keyed by the **platform** session id (`ndjsonEventLog(dir).forSession(sessionId)` as the `serveSession` `eventLog`) — a runtime names its sessions its own way. `session.opened.head` is the served head, `(0, 0)` before any event; `hello.resume` is the later of the served head and the last frame sent. Because `serveSession` replays whatever the store holds when its buffer has moved on, the daemon's pump checks each frame follows the last (next seq, or seq 1 of a later epoch) and sends a `gap {from: wanted, resumeAt}` before a hole. A wanted session the daemon no longer runs (restart) is replayed from its log, then `session.closed`. `session.open` is refused with a reason for an unknown environment, a runtime without a driver, a `cwd` outside `cwdRoots`, or a full environment (`concurrency`). Background running on Windows is a per-user Scheduled Task (`apps/daemon/scripts/install-service.ps1`), not a LocalSystem service, because the token and every `CLAUDE_CONFIG_DIR` belong to the user.
- **Machine actor** (`packages/platform/src/machine`, #36): `defineMachineActor({ socket, sessions, tools?, heartbeatWindowMs?, commandTimeoutMs? })`, keyed `{ws}:machine:{id}`, save persistence. `pair(code, info)` redeems the code through `Workspace.claimPairing` over a hop and stores only the token hash (`tokenRecord()` is what `authenticate`'s `machines` lookup and the socket handshake verify against; `revoke()` refuses the token from then on and closes the socket). The host owns the socket: on Cloudflare (`apps/web/src/daemon`) the Worker forwards `/_agentic/daemon/{machineId}` to the Machine's own Durable Object, which verifies `Authorization: Bearer amt.…` against `tokenRecord`, accepts the server end with the hibernation API under the `agentic:daemon` tag, and hands every text message to `socketMessage(raw)` under the machine principal; a close or error calls `socketClosed()` (offline at once). Outbound frames go through the `MachineSocketPort` (actor key → `state.getWebSockets(tag)`). `hello` records os / version / environments / capabilities, answers `welcome {wanted}` from the cursor the machine last forwarded per hosted session (`{0,0}` when none), re-sends `session.open` for sessions the daemon never acknowledged and every pending command (replies are idempotent by `commandId`); `env` replaces the environments; `heartbeat` / `pong` refresh `lastSeen`. The stored descriptors carry the daemon's per-environment `doctor` verdict, and `doctor(environmentId?)` → `MachineDoctorView { ok, unverified, environments: [{ environmentId, name, runtime, account, isolation, verdict? }] }` returns them as stored (never recomputed — the platform cannot see a config dir): `ok` only when every environment has a verdict and none is an error; this is the `environments.doctor` shape for the MCP surface (#50) and the Machines page (#90). `openSession(sessionId, environmentId, spec, {taskId?})` → `opened` when the environment has a free slot (`concurrency.max` minus hosted sessions) or `queued` until one closes; `closeSession` sends `session.close` (or drops a queued one); `session.opened` binds the session and forwards a synthesized wire `hello` (ref + capabilities, since the daemon's pump skips it) to the Session; `session.frame` → `Session.forwardFrames`, `session.reply` → `Session.commandReplied`, `session.closed` frees the slot, answers that session's pending commands `closed` and dequeues the next; `tool.call` runs on the `ToolCallPort` under `mintAgentPrincipal({ws, agentId, sessionId, taskId?})`, detached from the socket turn, and answers `tool.result`. `sendCommand(sessionId, command)` (the app binds the Session's `CommandSink` to it) records `pending {sessionId, command, sentAt, deadline}` and sends while online; the `liveness` reminder (60 s floor) marks a machine offline after `heartbeatWindowMs` (90 s) of silence and answers commands past their deadline (120 s) with `error internal`. Session hops are fresh `actor()` calls under the machine principal (never `ctx.actor`): the daemon-path entry points admit only the hosting machine, and `sendCommand` may run inside the Session's own turn — the not-hosted `closed` reply is `oneWay` so it never waits on the turn waiting on it. With #37 the machine also tells the Routing actor — one-way, as itself, when `MachinePorts.routing` is set — `machineOnline` on every `hello`, `sessionOpened` when the daemon acknowledges a hosted session (a dequeued one included) and `sessionClosed` when one is gone, so a task parked on the machine resumes or fails with the daemon's reason (a session refused before it opened fails its task `session-refused`); the anonymous `POST /auth/pair` resolves the code through the global `PairingDirectory` (filed by `Workspace.registerMachinePending`, single use) and then calls `Machine.pair(code, info)` as that machine. Open seam: the Session actor still has no entry point for a host-side closure of a session that already opened.
- Envelope contract (`@agentic/daemon-protocol`): one frame per WebSocket text message; `v` is checked before `t` before the schema, so a peer on another version is refused with `unsupported-version` and a malformed message with one of `too-large` (1 MiB, checked before parsing) · `not-json` · `not-object` · `unknown-type` · `invalid`. Every frame kind has a Standard Schema (zod) with bounded strings and lists (`LIMITS`); unknown keys are stripped. A daemon drops what it cannot decode and keeps the socket. `session.frame` traffic waits for `welcome`, so a replay driven by `wanted` always precedes live frames; `wanted` is the last cursor the platform holds and replay starts right after it; a cursor older than the log yields a `gap` frame, never silence. `daemonConformance(harness)` on `@agentic/daemon-protocol/testing` pins all of this from the platform seat (hello/welcome, malformed input, env, heartbeat, session, reconnect replay, gap, tool round trip); `inMemoryHarness()` is the reference daemon it is proven against and a stand-in for tests of the Machine actor.

## 6. Chat model

Entries: `msg {author: user | agent{agentId, sessionId?}, parts, mentions, replyTo?, sessionId?, taskId?}`, `member {op: add | remove, agentId, historyAccess}`, `status {agentId, kind: typing | session-started | session-ended | task, ref}`, `coordinator {agentId | null}`.

- Activation (CHT-06): activated = mentions ∩ members; none → coordinator if set; none and exactly one agent member → that agent; otherwise store only. `mentions: 'all'` addresses the group (every agent member). An agent's own post never activates itself. Agent-originated posts may mention other agents (COL-06) with the depth counter from the originating Task.
- Each activation creates a Task (origin = user message, context = entries visible to that agent since `historyFrom`) and opens or reuses one Session per (chat, agent) when the runtime supports resume.
- Streaming deltas never pass through Chat: the UI subscribes to `Session.tail` for `chat.activeSessions`. Chat receives only final assistant messages and status through a topic subscription — `topic(SESSION_EVENTS_TOPIC, chatKey)` carrying a `SessionEvent` (`status` → a `status` entry that also maintains `activeSessions`; `message` → a `msg` entry attributed to the agent). `typing` is ephemeral and never made durable (CHT-11: a chat coordinates N sessions, never one provider conversation).
- History access (CHT-04): `members[agentId].historyFrom` is the index of the join entry (`'all'` → 0); `history`/`search` filter `seq >= historyFrom` when the caller is an agent principal, and an agent that is not a member reads nothing; context assembly uses the same rule; removal closes the agent's session for that chat. Membership and the coordinator are changed by user or external principals only; machines never post.
- Memory privacy (MEM-11): retrieval runs under the assignee's principal against its own scope + declared shared scopes; `Memory.authorize` enforces it.

## 7. Task and delegation

`queued → active → (waiting ⇄ active) → completed | failed | cancelled`; `waiting` always carries a `WaitReason`.

Driver (`Task.tasks.run`): resolve environment (fixed at creation; offline → `waiting {environment-offline}` and the agent's policy `queue | fail | fallback-api`, the last only when explicitly allowed — never silent) → `Agent.snapshotForSession` → `Session.open` → retrieve memories → prompt → mirror session state → result (`verified: false` unless a verification step set it, LRN-03) → learning hook.

**DelegateTool** (`packages/runtimes/src/tools/delegate.ts`, a `defineTool({name: 'delegate', annotations: {openWorld: true}})`): `execute` calls `Task.delegate(spec)`, which checks collaborators, depth, concurrency and budget split, creates the child with the deterministic id `(parentTaskId, callId)`, moves the parent to `waiting {child}`, then awaits the child's `Task.result` stream (idempotent across restarts). In-process `agentTool` is used only for `modelAgent` named sub-agents within one session, never across machines.

Stop cascade (COL-12): `Task.cancel` → `Session.cancel` → each child (one-way) → wait for acks with a deadline → unacked children recorded `stopped: false` and listed as "could not be stopped".

As implemented (`packages/platform/src/task/`): `cancel(by, {timeoutMs})` transitions to `cancelled`, then calls `stop(by, deadline)` one-way on every unsettled child; a child acknowledges its parent through `childStopped(id, report)` (a reentrant method, so it lands while the parent's turn is parked on the deadline) after settling its own subtree, and each hop keeps a 20 % margin of the remaining time so the child's report precedes the parent's deadline. A task with a session attached also waits for `sessionStopped()` from the session driver (the `Session.cancel` hop above); until that arrives it lists itself in `notStopped`. Children report terminal states to the parent with `childSettled(id, status)`, which frees the child's budget reservation and resumes a parent parked on `waiting {child}` once its last waited-on child settles. Limits default to `maxDepth 5` and `maxConcurrentChildren 8` when the contract sets none; the budget split clamps each of `maxCostUsd`/`maxTokens`/`maxWallMs`/`maxTurns`/`maxSteps` to the parent's remaining share after its own spend and live reservations, never widening. Budget exhaustion (#45, COL-11/OPS-08): `recordUsage` and `delegate` run `checkBudget(constraints, spent)` from `packages/platform/src/ledger`; once a budget is spent (`spent >= max`, estimates counted in full) the task ends `failed` with `error.code 'budget'`, cancels every unsettled child one-way (a queued child is cancelled before it ever starts), and `delegate` throws `TaskLimitError('budget')` before creating anything — distinct from the split's "nothing left to delegate", which refuses the child but keeps the parent alive. Every mutation is one `TaskEntry` through the pure reducer `applyTaskEntry` — `ctx.append` where the runtime ships it, the reducer plus `ctx.save()` otherwise — so the record is snapshot + log either way.

Approvals across delegation (AC-12): children run under `firstMatch(childPolicy, parentConstraints)` (never wider); a child `request` bubbles `waiting {child}` to the parent; the user's decision goes to the child session.

**Delegation, as implemented** (#39, `packages/platform/src/routing/tools.ts`, `packages/platform/src/policy`, `packages/runtimes/src/tools/delegate.ts`): `createActorToolPorts().task.delegate` serves the `delegate` tool on BOTH paths (in-process inside `modelAgent`, and through the Machine's `tool.call`): it checks the parent agent's `collaborators` (COL-10, `forbidden`), calls `Task.delegate` (depth, concurrency, budget split, child id `childTaskId(parentTaskId, callId)`, parent → `waiting {child}`; a `TaskLimitError` answers `limit`), hands the child to `Routing.run` — a 409 (already routed, or already settled because a restarted parent re-issued the call) is not an error — and awaits the child's `Task.result` stream, so the same call id always finds and re-awaits the same child. The tool result is `{ taskId, status, text?, output?, artifacts, verified, error?, notStopped? }`; on the local path the tool also emits an `agent-start` / terminal `agent-update` pair bound to its call (`AgentToolContext.emit`) so the UI renders a sub-agent card linking to the child task — the child's own events are never nested into the parent transcript (it may run on another machine). A child runs on ITS agent's runtime and environment with no chat (`origin.kind === 'agent'`): background collaboration whose record is the Task tree and its transitions (COL-08/09). Approvals (AC-12): the child's `Route` carries `constraints` — the parent route's chain plus the parent's own `approvalPolicy` — into `SessionOpenSpec.approvalConstraints`, and `createSessionFactory` opens every local session under `sessionPolicy(spec)` = `constrainPolicy(agentPolicy(config), compilePolicy(constraints))`, where `agentPolicy` is `firstMatch(compilePolicy(approvalPolicy), grantPolicy(tools), allowAll)` and `constrainPolicy` lets the stricter side win (deny > ask > allow) so a child is never wider than its ancestors (the daemon path's policy is #40's). A child `request` parks the child `waiting {approval | input, requestId, sessionId}` (the parent already `waiting {child}`), and — when `RoutingPorts.inbox` is wired — pushes an `approval` / `input` Inbox notification with a session ref; the user answers with `Session.respond` on the CHILD session. Stop (COL-12): the router's `follow` is the Task's session driver — a task settled from outside while its turn runs (cancelled by a user or a parent's cascade, failed on budget) has its session cancelled, and `Task.sessionStopped` is sent when the turn actually ends; a late confirmation (`sessionStopped` or a child's ack after the cascade settled) is re-acknowledged upward so every ancestor's `notStopped` is corrected. An aborted parent turn answers `cancelled` with `notStopped` naming the child when its stop is not yet confirmed. `follow` itself is one supervisor task per router (`ctx.tasks` is single-flight per name) that follows every `running` route at once and is woken by `prompt`.

**Routing, as implemented** (#37, `packages/platform/src/routing`): the driver is the Routing actor, `{ws}:routing:main`, `defineRoutingActor({ sessions, machines })` (thunks — Session, Machine and Routing reference each other). `run(taskId)` on a `queued` task takes `Agent.snapshotForSession`, resolves the runtime and the environment ONCE (the task's `environmentId`, else the agent's `defaultEnvironmentId`) and records both on a `Route`; nothing later changes them (EXE-12) — a retry always goes to the machine that reported the environment at resolution, never to another machine reporting the same id. `anthropic-api` opens a local Session through the concrete `SessionFactory` (`createSessionFactory({ routing, anthropic })` → `createPlatformModelAgent` over the actor tool ports, BYO key per workspace, `no-api-key` when none) and prompts `objective + context` under the turn id `{taskId}:turn:1` (idempotent). A daemon runtime opens the Session record first (mode remote), then `Machine.openSession(sessionId, envId, OpenSpec, { taskId })`: `opened` → Task `active`, prompted when the machine reports `sessionOpened`; `queued` → Task `waiting {capacity, position}` (the position in the machine's queue), prompted on `sessionOpened` after a dequeue with a `waiting → active` transition that says so; machine offline → Task `waiting {environment-offline, policy}` then the agent's `offlinePolicy`: `queue` parks the route until `machineOnline` from THAT machine, `fail` ends the task `failed {environment-offline}` naming the environment, machine and policy, `fallback-api` — only when the config sets it — opens a NEW local session through a `waiting → active` transition whose `why` starts with `fallback-api:` and names the environment (the task's own `environmentId` stays what it was; the record says where it actually ran). An environment no machine of the workspace reports yet is offline under the same policy (`queue` waits for the first machine that reports it and binds the route to it then; `fail` ends the task `failed {environment-offline}` saying no machine reports it); an agent without an environment, or one whose runtime differs from the environment's, fails the task with a code (`no-environment`, `runtime-mismatch`). The `follow` actor task tails the Session and settles the Task at the turn end: `completed` with the final assistant text (or the `task_report` summary) and the `task_report` output when one was given, `failed` on an error, `waiting {input}` "Resume?" on an interrupted turn (OPS-05/06), `waiting {approval | input}` / back to `active` on `request` / `request-resolved`; then the session is closed so the environment slot frees. Routing drives the other actors as the workspace user (v1: `workspaceId === userId`; `RoutingPorts.driver` overrides). `run` also adopts a task the schedule trigger (#42) left `waiting {environment-offline}` — the app hands every task a firing creates to `Routing.run` from `scheduleTrigger({ onOutcome })`, and the trigger's `EnvironmentProbe` is `createEnvironmentProbe({ machines })` over the same machine scan. Platform tools (`memory_search`, `memory_remember`, `chat_post`, `task_report`, `delegate`) run over `createActorToolPorts` under the agent principal on both paths — in-process inside `modelAgent`, and through the Machine's `ToolCallPort` (`createToolCallPort`, the same tool definitions, `SchemaValidationError` → `invalid`); `ask_user` answers `unsupported` until #40. The local session policy is compiled from the config (`sessionPolicy`, #39); memory retrieval and the learning hook are #41's.

## 8. Memory and learning

Interfaces in `@agentic/core`:

```ts
interface MemoryPlugin { id: string; version: string; capabilities: { semantic: boolean; export: 'full' | 'partial' }; open(scope: MemoryScope, ctx: PluginContext): MemoryStore }
interface MemoryStore { put(e: NewMemoryEntry): Promise<MemoryEntry>; update(id, patch); retire(id, why); get(id); query(q: MemoryQuery): Promise<RankedMemory[]>; export(): AsyncIterable<MemoryEntry>; import(rows: AsyncIterable<MemoryEntry>, opts): Promise<ImportReport> }
interface MemoryQuery { text?: string; tags?: string[]; kinds?: MemoryKind[]; subject?: string; limit: number; since?: number }
interface LearningPlugin { id; version; onTaskEnd(ev: TaskOutcome, mem: MemoryStore): Promise<Proposal[]>; onCorrection(ev: Correction, mem: MemoryStore): Promise<Proposal[]> }
type Proposal = { kind: 'memory'; entry: NewMemoryEntry } | { kind: 'instruction'; patch: string; requiresReview: true }
```

Default memory (`@agentic/memory`, #26): a pure core — `MemoryState` + `applyMemoryLog` reducer, BM25 over text/tags/subject/`conditions` × kind weight (preference 1.3 > lesson 1.2 > fact 1.1 > working 1.0 > record 0.9 > assumption 0.8) × confidence weight × recency decay (30-day half-life, floor 0.5) — and `createMemoryStore({ state, now, commit })` over it. `query` filters on `tags` (any-of; `conditions` tokens count as tags), `kinds`, `subject`, `since`, ranks on `text`, and never exceeds `limit` (default 20) or `maxBytes` (default 4096 bytes of `text`; a non-fitting entry is skipped). `working` entries expire `ttl` ms after `provenance.at` and are compacted on the next working put; a new `record` for a task retires the previous ones (`supersedes`). `retire` is soft: hidden from `query`, kept for `get` and export. Export is NDJSON with a header `{ format: 'agentic-memory', version: 1 }`; `import` reports `imported` / `skipped` / `droppedFields`. `memoryConformance(make)` (`@agentic/memory/testing`) runs against the in-memory store and the Memory actor over `memoryStorage()`; the Durable Object run is a follow-up (#33).

The Memory actor (`@agentic/platform/src/memory`) is that store over `ctx.state` with `ctx.save()` per mutating turn (`ctx.append` once `@sigx/actors` ships signalxjs/actors#312). Methods: put, update, retire, get, query, exportPage, importBatch, compact, setAcl/getAcl, stats. Access: `memoryAuthorize` (same workspace; a user or a `memory`-scoped external client owns every scope; an agent only `agent:{self}`) and, inside the turn, the shared-scope ACL `{ read, write }` — no ACL, no agent access (MEM-04/11, AC-10). Embeddings later as a plugin via export/import (MEM-09) with the fidelity report.

Migration (`@agentic/memory`, #49, MEM-09): the export/import contract is the path between plugins, and `migrate(from, to, { dryRun, onConflict })` is the helper that walks it — every entry of `from` (retired included) imported into `to` kind by kind, returning a `MigrationReport` with `entries` / `imported` / `skipped` / `droppedFields` in total and per kind; a field is listed only when an entry of that kind carried it. A dry run asks the target's `fidelity(entry)` seam (`MemoryFidelity`, on every store of the package: the fields `import` would drop, `null` for a row it would skip) and `get` for id conflicts, so it reports the same numbers without writing; a target without the seam migrates for real only. The **flat plugin** (`flatMemoryPlugin()`, `agentic.memory.flat`, `capabilities.export: 'partial'`) is the deliberately narrower second implementation the path is proven against: it holds id, kind, text, tags, subject, provenance, confidence and `retired`, drops `conditions`, `evidence`, `supersedes` and `ttl` (`FLAT_UNSUPPORTED_FIELDS` — reported by `import`, by `fidelity`, and logged at `warn` by a `put` / `update` that carried one), ranks by the number of query terms found as substrings of `text` with recency as the tie-break (no kind or confidence weight, conditions are not tags), never expires a `working` entry and never compacts records. A round trip default → flat → default therefore reports exactly those four fields and nothing else (AC-11). `memoryConformance` marks the four cases those features need with `requires` (`conditions`, `kindWeights`, `ttl`, `supersedes`); a plugin runs the suite `without` the ones it lacks — the flat plugin all four, the default plugin and the Memory actor none. Retirement reasons are not part of `MemoryEntry`, so no export carries them: a limitation of the format, shared by every plugin.

Learning: explicit "Correct" action on any assistant message (v1); agent-detected correction classification is off by default. Memory writes are automatic; instruction/skill patches require review and land as new Agent config versions (AGT-06, LRN-08). Lessons retire through `supersedes` / `retire` (LRN-06). Copying a lesson into a shared scope keeps provenance (LRN-07). LRN-09: Ledger counts corrections per agent per week.

As wired (#41, `packages/platform/src/task/driver.ts` + the Session actor's `learning` port; the memory page is #89): the steps are pure functions the Session actor runs and a Task driver can reuse. **Session start** — `open` (before the factory or a daemon sees the spec) runs `retrieveMemories` **as the minted agent principal** over `agent:{id}` + `memoryPolicy.shared` (so `Memory.authorize` and the ACL decide, MEM-11; a refused scope is listed in `spec.retrieval.skipped`), ranked on `spec.objective` + the last text part of `spec.context`, filtered on `spec.tags`, merged under one budget (8 entries / 4096 bytes by default, MEM-07); the hits are recorded as `spec.memories` (the API factory renders them through `createPlatformModelAgent({ memories })`) and appended to `spec.system` as `## Platform memory` + an ownership note (MEM-10) — the heading `claudeCodeSystemPrompt` relabels to, so the daemon path carries it verbatim. **Turn end** — a task session's regular `turn-end` becomes a `TaskOutcome` (`end_turn`/`max_*` → completed, `cancelled`, else failed; a result with text is `claimed`, `verified`/`refuted` only from the `verify` port, LRN-03) for `plugin.onTaskEnd`; memory proposals are applied by the plugin, instruction proposals parked; an interrupted turn is no outcome. **Correct** — `Session.correct(messageId, text, what)` builds the `Correction` for the assistant message (`by: 'user'`, or `'agent'` for an agent principal; never a machine) and runs `plugin.onCorrection` as the agent, so the lesson lands in `agent:{id}` with the user's provenance. The plugin port may be a factory over `{ workspaceId, agentId, sessionId, taskId?, objective?, tags? }`, which is how `contextFor` gives a lesson the task's conditions. **Review** — instruction proposals park on the Agent actor (`propose` / `listProposals` / `reviewProposal`); an acceptance is a new config version with the patch appended to `instructions`, reversible by `rollback` (LRN-08). AC-09 is scripted end to end over `mockAgent` in `packages/platform/__tests__/session-learning.test.ts`.

Default learning (`@agentic/learning`, #27) works over any `MemoryStore`. `onCorrection` writes a `lesson` — `text` the correction, `evidence` one line per occurrence, `conditions` from `contextFor(correction)` (the task objective; the correction itself when unknown), `confidence: 'stated'`, `provenance.source: 'user'`; agent-detected corrections are dropped unless `acceptAgentCorrections`. A correction of the same `what` with ≥ 0.6 word overlap supersedes the live lesson (merged conditions, the newest `evidenceCap` evidence lines behind an uncapped `corrections in total: N` line, old one retired). The `repeatThreshold`-th repetition (default 3, and each multiple) adds an instruction proposal with `requiresReview: true`; nothing applies it here. `onTaskEnd` writes a `record` per task — `verified`/`refuted` are `confidence: 'verified'` + `source: 'verification'`, `claimed`/`none` are `assumed` + `agent`, the tag says which (LRN-03) — plus a lesson when a claim was refuted. Memory proposals are applied by the plugin (`apply: false` returns them instead); `applyProposals` is the one writer and runs `assertPermissionFree` over the batch first: no permission key (`permissions`, `grants`, `allowedTools`, `policy`, …) at any depth and no field outside `NewMemoryEntry` / the instruction shape, mirrored at the type level by `PermissionFree<T>` (LRN-08). `relevantLessons(memory, { objective, tags })` is the pre-task read: lessons only, no retired entry, no lesson sharing no word with the context. Counters go through the `CorrectionLedger` port (`recordCorrection({ agentId, week, what, at })`, ISO week in UTC); the Ledger actor (#45) implements it.

## 9. Plugins, MCP, A2A, auth

- `PluginManifest {id, version, kind: runtime | connector | memory | learning | notification | trigger | a2a, name, description, capabilities[], config: JsonSchema, permissions: [{scope, reason}], compat}`. v1 plugins are in-repo modules registered at build time. Registry holds enabled/config/grantedPermissions; `dependents()` lists agents/schedules referencing a plugin (AC-13). Nothing receives a secret unless `grantedPermissions` includes it (PLG-04). Notifications v1 (`packages/platform/src/notify`): the seam is `NotificationChannel {id, deliver(notification, {workspaceId, subscriptions}) → {ok, error?, expired?}}`; a `notification` plugin implements it and the app passes its instances to `defineInbox({channels})`. `Inbox.push` records first, then fans out through `deliverAll` — a channel that rejects or answers `ok: false` becomes a `DeliveryAttempt` on the record, never a throw (OPS-04). `webPushChannel({fetch, vapid, ttlSeconds})` POSTs one push per subscription with VAPID (RFC 8292) signed as ES256 over WebCrypto, so it is edge-safe; 404/410 endpoints are reported `expired` and the inbox drops them. **Gap:** v1 pushes are *contentless* — no RFC 8291 `aes128gcm` payload encryption — so the service worker treats a push event as "inbox changed" and re-reads `Inbox.list`; encrypted payloads (title/body in the push itself) are a follow-up. VAPID keys come from Workers Secrets (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`). Triggers v1: HMAC-validated webhook → Task.
- MCP client (`@agentic/mcp`): `createMcpClient({url, auth}).tools() → AnyTool[]` — Streamable HTTP over `fetch` (edge-safe, no SDK; JSON and SSE responses, `Mcp-Session-Id`, `notifications/cancelled` on abort); `@agentic/mcp/node` adds `createStdioMcpClient({command, args})` for servers the daemon spawns (via `@sigx/ai-agent-node` + `@sigx/ai-agent/harness` JSON-RPC). `tools/list` entries become `defineTool({ jsonSchema: inputSchema, annotations })` with the wire schema verbatim and hint-for-hint annotations; `isError` results throw `McpToolError` so the engine shows the model a tool error. `mcpConnector({id, transport, url | command, secret})` is the `PluginManifest` (kind connector) with `network:<host>` / `machine:<id>`, `secret:<name>` and `tools:<id>` permissions declared up front. `capabilityReport()` and the manifest's `unsupported:<op>` capabilities enumerate what the client leaves out — resources, prompts, sampling, elicitation, roots, logging, completions, tasks, `list_changed`, progress, the GET stream, resumption, OAuth discovery — and which of those a given server actually offers (PLG-09). Server-initiated requests are answered `-32601`, never dropped.
- **Platform MCP server = orchestration surface** (`/_agentic/mcp`, `createMcpToolHandler`). Design constraint from day one: every platform capability is an actor method, and both the web UI and the MCP server are thin projections over the same methods, so an external MCP client (Claude Code on a laptop, Claude Desktop, any MCP- or A2A-speaking orchestrator) can drive every daemon on every machine. Tool families, annotated readOnly/destructive so `allowReadOnly` composes: `machines.list`, `environments.list/doctor`, `agents.list/get`, `sessions.open(agentId, environmentId, cwd)`, `sessions.prompt`, `sessions.respond`, `sessions.cancel`, `sessions.tail(from)`, `tasks.create/delegate/get/tree/cancel`, `chats.post/history`, `memory.search/remember`, `schedules.create`. Machine selection is explicit in every call (EXE-12). Shipped (#50, `packages/mcp/src/server` + `packages/platform/src/auth/oauth-server` + `apps/web/src/auth/oauth-server`): wire names are `<family>_<op>` (`sessions_open`, …; `defineTool` names cannot carry a dot), the family IS the OAuth scope that gates it (`hasScope`, refused as an `isError` tool result naming the scope), and every tool runs over a per-principal `PlatformPort` — in the app a fresh `actor()` call per capability under the external principal, so each actor's own `authorize` chain decides; only the Workspace index read and `Routing.run` execute as the workspace's user (platform machinery, as the schedule trigger does). `sessions_open(agentId, machineId, environmentId, cwd?)` = Task.create with `origin { kind: 'external', clientId }` + `Routing.run`, after checking the named machine reports the named environment (404 otherwise, never a silent switch); `sessions_tail(sessionId, from?, limit?)` is a bounded page over `Session.events` with a `next` cursor. `tasks_delegate(taskId, agentId, objective, …, callId?)` = `Task.delegate` on the parent under the external principal (limits, depth, parent parked `waiting {child}`, COL-03) + `Routing.run` on the child as the driver, returning the child for `tasks_get` / `tasks_tree` to follow; `environments_doctor(machineId, environmentId?)` = `Machine.doctor` (#43). Declared gaps (`PLATFORM_MCP_UNSUPPORTED`): MCP resources and prompts. OAuth grant/revoke events are not on the Audit catalogue yet (`AUDIT_KINDS` has no `oauth.*` kind) — a follow-up once the catalogue grows.
  - **External-client OAuth (RFC 8414 / 7591 / 9728, OAuth 2.1).** `createOAuthServer({ secret, issuer, resource, store })` is pure `Request → Response` over WebCrypto and an `OAuthStore` (`memoryOAuthStore` in tests, `actorOAuthStore` over the global `OAuthClients` directory — anonymous `register`/`get`, like the `PairingDirectory` — and the per-workspace `OAuthGrants` actor `{ws}:oauth:grants`, owner-only). Public clients only (`token_endpoint_auth_method: none`), PKCE S256 required, redirect URI exact-match (loopback port excepted, RFC 8252), scopes = core's `Scope` union (`ALL_SCOPES`). Consent is a minimal HTML form rendered only for a signed-in user (else 302 to `/auth/login?returnTo=…`), sealed as an `oatx` transaction bound to that user; the user may untick scopes — the grant is the ticked subset. Tokens are HMAC-sealed on the package's `seal` envelope: `oacd` code (10 min, single use through the store), `oaac` access (1 h; decodes to `{ kind: 'external', workspaceId, clientId, scopes }`, `verify` also checks the grant is not revoked), `oarf` refresh (30 d, rotates on every use; a replayed generation revokes the grant), RFC 7009 revocation. The 401 on `/_agentic/mcp` carries `WWW-Authenticate: Bearer resource_metadata="…/.well-known/oauth-protected-resource/_agentic/mcp"`, which is all an MCP client needs: **`claude mcp add --transport http agentic https://<origin>/_agentic/mcp`** → the first request is challenged → the client reads the protected-resource metadata → the authorization-server metadata → registers itself at `/oauth/register` → opens the browser at `/oauth/authorize` (login, consent) → exchanges the code at `/oauth/token` → calls tools with the bearer, refreshing silently; no token is ever pasted. The MCP SDK asks for every scope the resource advertises, so narrowing happens on the consent screen.
- A2A 1.0, JSON-RPC binding only (`@agentic/a2a`, #31): `createA2aHandler({port})` is a fetch handler over a `SessionPort` (`agents()` = the agents flagged `exposeA2A`, `session(agentId, contextId, request)` = the live session behind a context, optional `authorize`) and a `TaskStore` for snapshots — no actors in the package. Mapping: contextId = session, task = turn (task id = turn id), text/reasoning parts = artifact chunks, `request` = INPUT_REQUIRED answered by a message on the task, other events (tool calls, usage, errors, the turn result) = data parts under the `agentic` extension (`required: false`, a plain peer sees text only). State mapping: SUBMITTED = queued, WORKING = active, INPUT_REQUIRED / AUTH_REQUIRED = waiting, terminals 1:1 (`turn-end` stop reasons: end_turn/max_* → COMPLETED, error → FAILED, cancelled → CANCELED, refusal → REJECTED). The full event table lives in `packages/a2a/README.md`.
- Principals: `{kind: 'user', userId, workspaceId}` (GitHub OAuth behind an `AuthProvider` interface → `__Host-session` cookie → `createServerApp({authenticate})`), `{kind: 'machine', workspaceId, machineId}` (pairing code: 6 chars, 10 min, single use → machine token, hash stored), `{kind: 'agent', workspaceId, agentId, sessionId, taskId}` (minted per session for tool callbacks), `{kind: 'external', clientId, scopes[]}` (OAuth 2.1 + Dynamic Client Registration, RFC 8414/7591/9728, so `claude mcp add --transport http agentic <url>` needs no manual token; scopes gate tool families).   - Auth seams (#32, `packages/platform/src/auth`, bound in `apps/web/src/auth`): `serverAuth({ sessionSecret, machines })` → `{ authenticate, codec }` for `createServerApp<Principal>`. Precedence: `Authorization: Bearer amt.<ws>.<machine>.<secret>` → machine principal (SHA-256 looked up on the Machine actor through the injected `MachineTokenLookup`; `revokedAt` → anonymous), `Bearer agt.…` → sealed agent principal, else `__Host-session` (HMAC-SHA256 seal of `{ userId, workspaceId }`, 30 days) → user principal; anything else `null`, never a throw. In-process callers with no request (task bodies) act as a minted agent via `actor(Def, key).with({ context: asPrincipal(principal) })`. v1 identity: personal workspace, `workspaceId === userId === gh_<github id>` (colon-free so `workspaceOfKey` parses every actor key). Pairing: `issuePairing` stores only the code hash on Workspace; `POST /auth/pair { code, name }` verifies (used → expired → mismatch), consumes, and returns the one-time machine token. Stored API keys: `encryptSecret(importWorkspaceKek(WORKSPACE_KEK), value, aad)`.

Retention (OPS-10, `docs/retention.md`): workspace settings `{sessionLogDays, artifactDays}`; `exportAll` writes one NDJSON file per actor kind plus `manifest.json` through the `ArtifactSink` port (R2 in `apps/web`), every row read through the owning actor's `get` / `export` as the owner (a task body inherits no principal, so the cascade calls `actor(Def, key).with({ context: asPrincipal(owner) })`), secrets by name only; `deleteAll` purges every child record the index implies (agents, their memory scopes, chats + pages, schedules, inbox, registry) plus whatever `WorkspaceStore.list` returns (tasks, sessions), then `clearState()`s itself (`apps/web` purges each record inside its own Durable Object via `POST /_agentic/purge`, `SESSION_SECRET`-authenticated, and has no `list`, #100) — tested to leave no record in storage; copies handed to runtimes, providers and peers are listed as outside platform control. The shell (`packages/ui/src/shell`, `AppShell`) is the handoff's: a sticky 232 px sidebar (`--ag-sidebar-w`; brand, nav `groups` — Primary unlabelled, Workspace headed — each a `<nav aria-label>`, per-item `badge`, then the `connection` and `user` slots) beside a 60 px topbar (`--ag-topbar-h`; `breadcrumb` and `actions` slots on zero's `Navbar`) and `<main>` (padding 28, `flush` for Chat); below 768 px the sidebar becomes zero's modal `Drawer` (312 px, 50 px items, connection strip at the foot, 200 ms slide off under reduced motion) behind a 44 px menu button and the topbar a 60 px app bar on base-200 — menu or `back`, `title` with the `subtitle` slot, one right slot (`phoneAction`, else the last action); one hand-written `shell.css`; router-agnostic (the app renders `Link` through the `link` and `back` slots). Per-screen grids live in `apps/web/src/styles/pages.css`, one section per page, plus the two responsive blocks of the handoff's single 768 px breakpoint: 768–1279 the fixed rails drop under the main column (Home, Task, Session, Machine, Memory), Chat keeps list + thread with the context panel in an end drawer behind the topbar's tasks button, three-column card grids become two; below 768 every grid is one column, `DataTable` stacks its rows into captioned cards from CSS alone (`--ag-col-N` on its wrapper, no second markup), the composer docks with 48 px controls, buttons are 48 px and split a row evenly, the environment card folds to a 52 px row, the message meta drops its environment line. The topbar is the route's: `apps/web/src/crumbs.ts` builds the trail (the section root plus the page's entity name from its `defineTopbar` contribution) that is the one-line breadcrumb at ≥ 768 px and the app bar's title + back link below; pages register their actions, sub-line and phone action in `components/topbar.ts`, never in an in-content head row. Playwright runs at 400 / 1024 / 1280 (`apps/web/e2e`, the CI `e2e` job). `themeInitScript` reaches `<head>` through `useHead`; `installThemes()` runs once per entry; a per-request `ThemeProvider` serves `useTheme()` on the server. The app's `build` runs `sigx zero:validate` against the consumed design system first, so CI validates it. No virtualised list in zero: the thread windows its own rows.
- Forms (`packages/ui/src/forms`): every configuration surface edits a draft bound through zero's `model=` contract (`Field` + labelled control, `Field.Error` wired by `aria-describedby`) and posts the same field names pre-hydration; one model module per form (`agent-model.ts`, `settings-model.ts`) owns config ⇄ draft ⇄ `FormData` and validation, so the live and posted paths cannot drift. A valid submit writes back through the model and emits; persistence (the Agent actor's versioned config, Workspace settings) is wired by the pages. The approval editor owns one rule per tool category (`id: category:<name>`, first in the policy); every other rule is carried through untouched. Multi-selects use `_zero-gaps/multi-select.tsx` until zero ships a multiple mode (andtii/zero-wip#479). The Agent config page (`apps/web/src/pages/agent/ConfigTab.tsx`, #89) renders `AgentForm` in its `sections` layout with the segmented approval control and puts the save card (only while `dirty()`) and the versions rail (`VersionItem`: proposed / current / past) in the form's `rail` slot; the memory tab (`MemoryTab.tsx`) is the handoff's row grid over `MemoryEntry` with filter chips per kind; the sessions tab shares the Machine page's sessions table columns (`SESSIONS_COLS`). Agent pages read `apps/web/src/mock/agents.ts` until #35 / #41 wire the Agent and Memory actors.
- Failure distinction (OPS-04) from four signals: client socket status, `Machine.online`, environment `authStatus`, adapter `error` events, `Task.status` — each rendered by its own `FailureCard` kind (`kit/states`), never a generic error. Recovery (OPS-05): interrupted turns are marked, never auto-replayed; "Resume" issues a new prompt over the intact transcript.

## 11. Zero feedback loop

This app is the dogfood consumer for `@sigx/zero`. Friction (a missing part, a state the anatomy cannot express, a control that fights the model binding, a recipe the validator rejects) is filed on andtii/zero-wip labelled `from:agentic` as it is found, linked from the sub-issue here, with the smallest workaround under `packages/ui/src/_zero-gaps/`. Zero is never patched or vendored in this repo.

## 12. Risks and chosen defaults

| Risk | Default |
|---|---|
| Durable Object eviction during long model calls | task-based driver, append per event, "interrupted, resume?" |
